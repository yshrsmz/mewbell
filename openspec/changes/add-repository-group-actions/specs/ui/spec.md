## ADDED Requirements

### Requirement: リポジトリの見出しの操作

ポップオーバーの一覧のリポジトリの見出しには、ブラウザで開かずにそのグループのスレッドをまとめて既読にする「既読にする」と、まとめて Done にする「Done にする」の操作がなければならない（SHALL）。2 つの操作は、見出しにマウスを載せている間だけ見出しの右端にボタンとして表示し（SHALL）、同じ 2 つを見出しのコンテキストメニュー（右クリック）と、VoiceOver の操作（アクセシビリティのアクション）にも出さなければならない（SHALL）。グループを折りたたんでいても、同じように出さなければならない（SHALL）。ボタンにはツールチップとアクセシビリティのラベルを付け、どのリポジトリへの操作かが分かるようにしなければならない（SHALL）。どの操作でもブラウザを開いてはならず（MUST NOT）、ボタンを押したときに見出しの折りたたみが同時に起きてはならない（MUST NOT）。ボタンを出している間も、見出しの高さとリポジトリ名の書き出しの位置を変えてはならない（MUST NOT）。ボタンを出している間は、リポジトリ名と折りたたんだときの件数をボタンに重ねてはならず（MUST NOT）、収まらないときはリポジトリ名をボタンの手前で中央を省略しなければならない（SHALL。「ポップオーバーの文字の読みやすさ」の省略のしかた）。

「既読にする」は、押したらすぐに polling「リポジトリのグループの既読化と Done」に従って既読にしなければならない（SHALL）。

「Done にする」は、取り消せず複数のスレッドに効くので、1 回目に押したときはリクエストを送らずに、ボタンを件数を含む確認の表示（`Mark N as done?`。N はそのグループのスレッドの件数）に変えなければならない（SHALL）。コンテキストメニューと VoiceOver の操作で「Done にする」を選んだときも、すぐには行わずに、見出しのボタンを同じ確認の表示にしなければならない（SHALL）。確認の表示は、マウスを見出しから外しても出し続けなければならない（SHALL）。確認の表示のまま 5 秒以内にそのボタンを押したときだけ、polling「リポジトリのグループの既読化と Done」に従って Done にしなければならない（SHALL）。VoiceOver の操作で確認の表示にしたときは、確認を待っていることを読み上げで知らせなければならない（SHALL）。5 秒たったとき、ポップオーバーを閉じたとき、そのグループのスレッドが変わったとき（件数と最新のスレッドが同じでも、スレッドが入れ替わったときを含む）、グループが一覧から消えたときは、リクエストを送らずに元の表示に戻さなければならない（SHALL）。確認の表示は操作したグループの見出しだけに出し、ほかのグループやアカウントの見出しに影響してはならない（MUST NOT）。確認の文は、アカウントのすべて既読の確認と同じく、アクセントカラーで出さなければならない（SHALL）。

#### Scenario: ホバーで操作が出る

- **GIVEN** `github.com/alice` の一覧に `octo/app` のスレッドが 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しにマウスを載せる
- **THEN** 見出しの右端に「既読にする」と「Done にする」のボタンが出る
- **AND** マウスを見出しから外すとボタンは消える

#### Scenario: グループを既読にする

- **GIVEN** `octo/app` の見出しにマウスを載せている
- **WHEN** ユーザーが「既読にする」のボタンを押す
- **THEN** ブラウザは開かず、`octo/app` のグループが一覧からすぐに消え、グループのスレッドごとに `PATCH /notifications/threads/{id}` が送られる
- **AND** `octo/app` の見出しは折りたたまれない

#### Scenario: 2 回押してグループを Done にする

- **GIVEN** `octo/app` の見出しにマウスを載せていて、グループに 2 件ある
- **WHEN** ユーザーが「Done にする」のボタンを押す
- **THEN** ボタンは `Mark 2 as done?` の表示に変わり、リクエストは送られない
- **AND** 5 秒以内にもう一度押すと、`octo/app` のグループが一覧から消え、グループのスレッドごとに `DELETE /notifications/threads/{id}` が送られる

#### Scenario: コンテキストメニューで Done を選ぶ

- **GIVEN** `github.com/alice` の一覧に `octo/app` のスレッドが 3 件ある
- **WHEN** ユーザーが `octo/app` の見出しを右クリックし、「Done にする」を選ぶ
- **THEN** リクエストは送られず、見出しのボタンが `Mark 3 as done?` の表示になる
- **AND** 5 秒以内にそのボタンを押すと、グループのスレッドが Done になる

#### Scenario: コンテキストメニューで既読にする

- **GIVEN** `github.com/alice` の一覧に `octo/app` のスレッドが 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しを右クリックし、「既読にする」を選ぶ
- **THEN** 確認の表示にはならず、`octo/app` のグループが一覧からすぐに消える

#### Scenario: Done の確認のまま時間が過ぎる

- **GIVEN** ユーザーが `octo/app` の「Done にする」を 1 回押し、確認の表示になっている
- **WHEN** 5 秒がたつ
- **THEN** ボタンは元の表示に戻り、リクエストは送られない

#### Scenario: 確認の途中で新着が届く

- **GIVEN** ユーザーが `octo/app` の「Done にする」を 1 回押し、`Mark 2 as done?` の表示になっている
- **WHEN** 5 秒以内の取得で `octo/app` の新しいスレッドが届き、グループが 3 件になる
- **THEN** ボタンは元の表示に戻り、次に押しても確認の表示になるだけでリクエストは送られない

#### Scenario: 確認の途中でスレッドが入れ替わる

- **GIVEN** `octo/app` のグループにスレッド `1`（12:30）と `2`（12:00）があり、ユーザーが「Done にする」を 1 回押して `Mark 2 as done?` の表示になっている
- **WHEN** 5 秒以内の取得で `2` が消え、`octo/app` のスレッド `3`（11:00）が一覧に出る
- **THEN** ボタンは元の表示に戻り、次に押しても確認の表示になるだけでリクエストは送られない

#### Scenario: 折りたたんだグループを Done にする

- **GIVEN** `octo/app` のグループを折りたたんでいて、見出しに `2` と出ている
- **WHEN** ユーザーが見出しの「Done にする」を 2 回押す
- **THEN** 隠れていた 2 件のスレッドが Done になり、`octo/app` の見出しが一覧から消える

#### Scenario: ほかのグループに影響しない

- **GIVEN** `github.com/alice` の一覧に `octo/app` と `octo/lib` のグループがある
- **WHEN** ユーザーが `octo/app` の「Done にする」を 1 回押す
- **THEN** `octo/app` の見出しだけが確認の表示になり、`octo/lib` の見出しとアカウントのすべて既読のボタンは変わらない

## MODIFIED Requirements

### Requirement: ポップオーバーの押せる要素のホバーの反応

ポップオーバーの次の要素は、マウスを載せている間、押せる範囲に薄い塗りを出して、押せることと押したときに反応する範囲が分かるようにしなければならない（SHALL）。押している間は、マウスを載せているときより濃い塗りにしなければならない（SHALL）。

- アイコンだけのボタン: 見出しの歯車と再読み込み、スレッドの行の「既読にする」と「Done にする」、リポジトリの見出しの「既読にする」と「Done にする」（確認の表示のときも含む）、アカウントの見出しの Web の通知一覧のボタンとすべて既読のボタン（確認の表示のときも含む）、コマンドの行のコピーのボタン
- スレッドの行（クリックでスレッドを開く範囲）
- アカウントの見出しとリポジトリの見出しの、折りたたみの操作の範囲

塗りは、システムの文字色を薄く重ねた角丸の塗りにし、独自の色を使ってはならない（MUST NOT）。これは「ポップオーバーの文字の読みやすさ」が許すボタンの囲みの塗りであり、文字の色を変えてはならない（MUST NOT。すべて既読とリポジトリの Done の確認の文はアクセントカラーのまま）。マウスを外したら塗りを消さなければならない（SHALL）。押せないとき（再読み込み中の再読み込みのボタン、押せないすべて既読のボタン）と、折りたたみの操作を出さない見出しには、塗りを出してはならない（MUST NOT）。塗りを出しても、行と見出しの高さ、アイコンと文字の位置、件名の折り返しは変えてはならない（MUST NOT）。

スレッドの行では、行の塗りはマウスを載せた行の全体に出し、「既読にする」と「Done にする」のボタンを出している間も、ボタンの下を含めて行の全体に出し続けなければならない（SHALL）。ボタンにマウスを載せたときは、行の塗りの上にボタンの塗りを重ねて出さなければならない（SHALL）。リポジトリの見出しの折りたたみの操作の範囲は、見出しの行の幅いっぱいにしなければならない（SHALL）。リポジトリの見出しでは、「既読にする」と「Done にする」のボタンを出している間も、ボタンの下を含めて見出しの行の幅いっぱいに塗りを出し続け、ボタンにマウスを載せたときは見出しの塗りの上にボタンの塗りを重ねて出さなければならない（SHALL。スレッドの行と同じ）。アカウントの見出しの折りたたみの操作の範囲は、見出しの行のうち、Web の通知一覧とすべて既読のボタンの手前までの幅いっぱいにし（SHALL）、それらのボタンと重ねてはならない（MUST NOT）。

システム標準の押しボタン（Quit、Open Settings…、Open cli.github.com など）は、macOS の標準の見た目のままにし、独自の塗りを付けてはならない（MUST NOT）。

### Requirement: ポップオーバーの文字の読みやすさ

ポップオーバーに出す文字（一覧、取得の状態、操作の失敗、案内の文、件数、ボタンの文）は、11pt より小さくしてはならない（MUST NOT）（13pt・11pt は macOS のテキストスタイルの大きさで、`.body` / `.headline` が 13pt、`.subheadline` が 11pt）。スレッドの件名とアカウントの見出しのユーザー名は 13pt で出さなければならない（SHALL）。アカウントの見出しのユーザー名とリポジトリの見出し（`owner/name`）は見出しとして、太字（semibold 以上）にし、薄い色にせず標準の文字色で出さなければならない（SHALL）。

薄い色（システムの副次的な文字色）は、次の補足の情報にだけ使わなければならない（SHALL）: スレッドの行の番号・理由・更新日時、ホスト名とホスト種別、トークンの状態が取得中であることの表示（「Checking gh…」）、gh を探している途中であることの表示（案内画面の「Checking gh…」）、通知の取得中・取得できた時刻の表示（「Loading notifications…」「Updated …」）、未読が無いことの表示、折りたたんだときの件数。この一覧に無い文は、すべて標準の文字色で出さなければならない（SHALL）。例えば、トークンを取れないときやスコープ不足・認証エラーの案内、取得に失敗して待っていることの文（「Rate limited. Retrying at …」など）、操作の失敗、一覧を打ち切ったことの知らせがそうである。すべて既読とリポジトリの Done の確認の文は、確認の途中であることが分かるよう、システムのアクセントカラーで出さなければならない（SHALL）。

文字の色は、システムの文字色（標準・副次的）と、すべて既読とリポジトリの Done の確認の文のシステムのアクセントカラーだけを使い、文字色の指定に独自の色や透明度を掛けた色を使ってはならない（MUST NOT）。マウスを載せたときに件名をボタンの下で消すような、文字色ではなく見た目を重ねる処理は、この決まりに含めない。「コントラストを上げる」をオンにしたときは、薄い色の文字も含めて背景とのコントラストが上がらなければならない（SHALL）。ポップオーバー全体の背景はシステムのマテリアルのままにし、独自の背景で覆ってはならない（MUST NOT）。これにより「透明度を下げる」をオンにしたときは、システムの設定に従って背景が不透明になる。コマンドの行・案内の帯・バッジ・ボタンの囲みには、システムの色を薄く重ねた塗りを敷いてよい。

ポップオーバーのアイコンのうち書体で大きさが決まるもの（種類のアイコン、見出しの山形、トークンの状態、参加のみの印、ベル、ボタンのアイコンなど）は、11pt より小さい書体で描いてはならない（MUST NOT）。取得中の印（`ProgressView`）は、この決まりに含めない。アイコンの色は文字の色の決まりに含めない（種類のアイコン・山形・参加のみの印・ベルは薄い色、トークンの状態と警告は状態を表すシステムの色を使ってよい）。スレッドの行の種類のアイコン、見出しの山形、アカウントの見出しのトークンの状態のアイコンは、同じ幅の列（アイコンの列）の中央に置く。列に置く記号は書体で決まる大きさのまま描き、縮めて列に収めてはならない（MUST NOT）。記号は、倍率 1 と 2 のどちらの画面でも、マウスを載せているときも、欠けずに出なければならない（SHALL）。

文字を大きくしても、ポップオーバーの幅（380pt）は変えてはならず（MUST NOT）、横にスクロールさせてはならない（MUST NOT）。アカウントの見出しは 1 行に収めなければならない（SHALL）。幅が足りないときは、まずホスト名とホスト種別を省略し、それでも足りなければユーザー名の末尾を省略しなければならない（SHALL）。アクティブの印、折りたたんだときの件数、すべて既読とリポジトリの Done の確認の文は省略してはならない（MUST NOT）。リポジトリの見出しは 1 行に収め、収まらないときは中央を省略しなければならない（SHALL）。ユーザー名・ホスト名・リポジトリ名を省略したときは、その文字にマウスを載せたツールチップで全体を読めなければならない（SHALL）。省略していないときは、同じ文のツールチップを出してはならない（MUST NOT）。スレッドの件名は 2 行まで出し、それより長いときは省略しなければならない（SHALL）。

メニューバーのアイコンと件数、設定ウィンドウの文字には、この Requirement は適用しない。

#### Scenario: スレッドの行

- **GIVEN** `github.com/alice` の `octo/app` に、Pull request `#42`、理由 `review_requested` のスレッドがある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 件名は 13pt で標準の文字色で出る
- **AND** `#42`、理由、更新日時の行は 11pt で薄い色で出る
- **AND** `octo/app` の見出しは 11pt の太字で、標準の文字色で出る

#### Scenario: アカウントの見出し

- **GIVEN** `acme.ghe.com/dave`（使える、アクティブ）がある
