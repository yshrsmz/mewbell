# Proposal

## Why

M2 までで、未読の通知はポップオーバーを開けば見られるようになった。ただ、新しい通知が来ても知らせる手段が無く、メニューバーのアイコンからは未読があるかどうかも分からない。一覧のスレッドを開いても未読のまま残るので、見たものを片付けるには Web で既読にするしかない。

マイルストーン: M3「macOS 通知と既読」。

## What Changes

- 新しく届いたスレッドと、`updated_at` が進んだスレッドを、macOS の通知（`UNUserNotificationCenter`）で知らせる。1 スレッド 1 通知で、通知 ID は `<host>/<user>/<threadId>`。同じスレッドに動きがあったら同じ ID で出し直す
- アカウントの最初の取得（起動直後・アカウントが増えたとき・止まったアカウントの再開の後）で得た未読は通知しない。それ以降に増えたもの・進んだものだけを通知する
- 一覧から消えたスレッド（既読にした・Done にした・Web で既読にした）の通知を取り下げる。アカウントが一覧から消えたとき・止まったときは、そのアカウントの通知をすべて取り下げる。前回の起動で出した通知のうち、今は未読でないものも取り下げる
- macOS の通知をクリックしたとき、またはポップオーバーの一覧でスレッドをクリックしたときは、ブラウザで開いてから `PATCH /notifications/threads/{id}` で既読にする。既読にしたスレッドは、一覧と macOS の通知からすぐに消す（**BREAKING**: ui「通知のスレッドを開く」の「既読にしない」を改める）
- メニューバーの猫アイコンの横に、全アカウントの未読の合計を出す（0 件なら出さない、100 件以上は `99+`）
- 通知の許可を起動時に求める。許可されていなくても、一覧とバッジはそのまま動き、ポップオーバーに通知が切られていることと、システム設定を開くボタンを出す

## Capabilities

### New Capabilities

- `notifications`: macOS の通知を出す・出し直す・取り下げる規則、通知の中身、通知をクリックしたときの動き、通知の許可。config.yaml の capability の一覧にある `notifications` を、この change で初めて作る（M3 で増える振る舞いの中心で、polling や ui に入れると、それぞれの責務がぼやけるため）

### Modified Capabilities

- `github-api`: スレッドを既読にする `PATCH /notifications/threads/{id}` と、その状態コードの扱いを足す。トークンを送る相手の制限（オリジン検査）がこのリクエストにも掛かることを明記する
- `polling`: 既読にしたスレッドを一覧からすぐに外すことと、既読の後の取得を条件なしにすることを足す
- `ui`: 「通知のスレッドを開く」で既読にするように改める。メニューバーの未読バッジと、通知が許可されていないときの案内を足す

## Impact

- コード: 新しく `Mewbell/Notifications/`（通知を出す・取り下げる型、届いたスレッドとの差分を出す型、通知のクリックの受け口）。`Mewbell/GitHubAPI/GitHubAPIClient.swift`（`PATCH` の追加）、`Mewbell/Polling/AccountPoller.swift` と `NotificationStore.swift`（既読化、通知への受け渡し）、`Mewbell/App/`（`MenuBarExtra` のラベル、`AppDelegate` での通知の準備）、`Mewbell/UI/AccountSectionView.swift`（クリックで既読）、テスト
- トークン: 触れる。トークンを付けて送るリクエストに `PATCH /notifications/threads/{id}` が増える。トークンの取得・保持の仕方は変えず、今までどおりメモリ上の actor にだけ持ち、永続化しない。通知の本文と `userInfo` にトークンを入れない
- ネットワーク: 触れる。新しいリクエストも `GitHubAPIClient` の 1 か所で組み立て、アカウントの API ベースとのオリジン検査・リダイレクトの拒否・キャッシュなしを同じように掛ける
- URL を開く処理: 触れる。macOS の通知のクリックからもブラウザで開く。`userInfo` から戻ってきた値は、使う前にホスト名・ユーザー名・スレッド ID・URL のホストを検証し直す
- gh サブプロセス: 触れない
- 永続化: アプリは何も書かない。ただし、macOS が通知センターに出した通知（件名・リポジトリ名・アカウント名と、クリックで開く Web の URL を含む `userInfo`）は、macOS の側でアプリの終了後も残る
- README の現状の説明（「macOS の通知と既読化はまだできません」）を更新する
