# Proposal

## Why

アカウントの見出しとリポジトリの見出しの開閉の操作は、押せる範囲の高さが中身（山形・アイコン・文字）の高さしかなく、16〜18pt ほどである。macOS の Human Interface Guidelines は、コントロールの大きさを既定 28×28pt、最小 20×20pt としていて、今の見出しは最小を下回る。前の change（`update-popover-hover-feedback`）で押せる範囲を行の幅いっぱいに広げたが、高さは変えていないので、縦にずれると押し外しやすい。

マイルストーン: M4（設定と操作）で足した操作の見た目の手直し。新しい操作は足さない。SETUP.md のマイルストーンの表には行を足さない。

## What Changes

- アカウントの見出しとリポジトリの見出しの、折りたたみの操作の押せる範囲（マウスを載せたときの塗りの範囲と同じ）の高さを、既定の文字の大きさで 24pt にする（macOS のサイドバーの小さい行と同じ高さ）。中身がそれより高いときは中身に合わせる
- 見出しの上下に余白が付くので、見出しの見た目の高さも伸び、一覧が少し縦に長くなる
- 折りたたみの操作を出さない見出し（トークンを取れない、最初の取得の前など）も同じ高さにする（畳めるようになったときに、見出しの高さが変わって一覧がずれないように）
- 見出しのアイコンのボタン（Web の通知一覧、すべて既読）、スレッドの行、ポップオーバーの上の見出し（歯車・再読み込み）の大きさは変えない

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `ui`: アカウントとリポジトリの見出しの、折りたたみの操作の押せる範囲の高さの下限を足す（新しい Requirement）。既存の「ポップオーバーの押せる要素のホバーの反応」の「塗りを出しても高さを変えない」は、マウスを載せる前後で高さが変わらないことを求めるもので、この change でも守る

## Impact

- コード: `Mewbell/UI/ListLayout.swift`（見出しの高さの寸法を足す）、`Mewbell/UI/DisclosureButton.swift`（見出しの中身に高さの下限を付ける）、`MewbellTests/`（見出しの高さを `NSHostingView` で測るテスト）
- 文書: `docs/architecture.md` の A16 に、押せる範囲の大きさ（縦横 20pt 以上、見出しの高さ）を書き足す
- トークン: 触れない
- gh サブプロセス: 触れない
- ネットワーク: 触れない
- URL を開く処理: 触れない
- 永続化: しない
