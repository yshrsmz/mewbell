# Proposal

## Why

アカウントの見出しのボタンが、スレッドの行とリポジトリの見出しのボタンと揃っていない。

- 大きさ: Web の通知一覧（`arrow.up.forward.square`）とすべて既読（`checkmark.circle`）は、書体はほかのボタンと同じ 13pt だが、囲みのある記号なので囲みの中に縮めて描かれる。そのため、リポジトリの見出しの `envelope.open` や `checkmark` より目に見えて小さい。押せる範囲も、ほかのボタンの 22pt 四方の枠ではなく、記号の外へ 3pt はみ出させた範囲で作っていて、形が違う
- 記号: すべて既読は既読の操作なのに、Done の `checkmark` に似た `checkmark.circle` を使っている。行とリポジトリの見出しの「既読にする」（`envelope.open`）と揃っていないうえ、Done に見える
- 出し方: 行とリポジトリの見出しのボタンはマウスを載せている間だけ出るが、アカウントの見出しのボタンは常に出ていて、見せ方が揃っていない
- 操作: 行とリポジトリの見出しには「既読にする」と「Done にする」があるが、アカウントの見出しには既読しかない。アカウントの通知を片付けるときに Done にする手段が無い。`add-repository-group-actions` では「アカウント単位の Done は足さない」を理由を書かずに Non-Goal にしていた

- ホストの表示: 見出しのホスト名の後ろに、ホスト種別を ` — ` でつないで出している（`github.com — GitHub.com`）。github.com では同じ名前が 2 回続くように見え、幅が足りないと中央が省略されて `github.co…itHub.com` になる。ホスト種別はホスト名から分かるので、見出しには要らない

見た目の一貫性とアクセシビリティ（小さい記号は見つけにくく、意味が操作と合わない記号は誤操作を招く）のために、アカウントの見出しのボタンを行とリポジトリの見出しのボタンと揃え、アカウント単位の Done を足す。

マイルストーン: M4「設定と操作」の追補。`add-repository-group-actions` で入れたまとめた操作を、アカウントにも広げる。

## What Changes

- アカウントの見出しのすべて既読のボタンの記号を、行とリポジトリの見出しの「既読にする」と同じ `envelope.open` にする
- アカウントの見出しの Web の通知一覧のボタンの記号は、四角の枠から矢印が出ていく `arrow.up.forward.square` のままにする（外部へ開くことを表す慣用の形のため）。大きさだけをほかのボタンに揃える
- アカウントの見出しのボタンを、リポジトリの見出しと同じく、見出しにマウスを載せている間だけ右端に出す。同じ操作を見出しのコンテキストメニューと VoiceOver の操作にも出す。すべて既読とすべて Done は、メニューと VoiceOver から選んだときも確認の表示にするだけにする。確認の表示はマウスを外しても出し続ける
- アカウントの見出しのボタンを、リポジトリの見出しのボタンと同じ大きさ（22pt 四方の枠）に揃える。見出しの高さ（24pt）は変えない
- アカウントの見出しに「すべて Done」のボタンを足す。記号は行とリポジトリの見出しの「Done にする」と同じ `checkmark`。ボタンの並びは、Web の通知一覧、すべて既読、すべて Done の順にする
- すべて Done は、押したときにそのアカウントの一覧に出していたスレッドだけを、リポジトリのグループの Done と同じ方法（スレッドごとに `DELETE /notifications/threads/{id}` を 1 件ずつ順に送る）で Done にする。まとめて Done にする API は無いので、一覧に出ていない未読（「参加しているスレッドだけにする」で取得していないもの、500 件で打ち切って取得していないもの）は対象にしない
- すべて Done は取り消せず複数のスレッドに効くので、すべて既読とリポジトリの Done と同じ 2 段階の確認（`Mark N as done?`、5 秒以内にもう一度押したときだけ実行）にする
- 1 つのアカウントの見出しで確認の表示にするのは、すべて既読とすべて Done のどちらか 1 つだけにする
- ポップオーバーのアカウントの見出しから、ホスト種別（GitHub.com / GHE Cloud / Enterprise Server）を外し、ホスト名だけを出す。設定ウィンドウの Accounts タブと Diagnostics のホスト種別は変えない（settings と diagnostics の spec が求めていて、幅にも余裕がある）

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `ui`: アカウントの見出しの操作（ホバーで出すこと、ボタンの配置、コンテキストメニューと VoiceOver）、ボタンの記号と大きさの要件、すべて Done のボタンとその確認の表示の要件を足す。「見出しの押せる範囲の高さ」の、アカウントの見出しのボタンの大きさを変えないとしていた一文を改める。「ポップオーバーの押せる要素のホバーの反応」「ポップオーバーの押せる要素のホバーの塗り」「ポップオーバーの押せる要素のホバーの範囲」「ポップオーバーの文字の読みやすさ」に、すべて Done のボタンとその確認の文を足す。「ポップオーバーの押せる要素のホバーの範囲」の、アカウントの見出しの折りたたみの範囲を、リポジトリの見出しと同じく行の幅いっぱいにする。「Web の通知一覧を開く」のボタンを、常に出すものからホバーで出すものに改める。「アカウント一覧の表示」「アカウント一覧の表示の通知の一覧」「ポップオーバーの文字の読みやすさ」「ポップオーバーの文字の読みやすさの文字色」「ポップオーバーの文字の読みやすさの幅と省略」から、見出しのホスト種別を外す
- `polling`: アカウントのスレッドをまとめて Done にする要件を足す。対象の決め方を定め、スレッドごとの扱い・リクエストの順・途中で止まったときの扱いは、既存の「リポジトリのグループの既読化と Done」の各要件に従わせる

`github-api` は変えない（既存の `DELETE /notifications/threads/{id}` をそのまま使う）。`notifications` の「通知の取り下げ」は、各スレッドが「スレッドの Done」を通るので、そのまま効く。

## Impact

- コード: `Mewbell/UI/AccountSectionView.swift`（見出しのボタンの並び、ホストの表示）、`Mewbell/UI/ThreadRow.swift`（`MarkAllReadButton`）、`Mewbell/UI/HoverActionButtons.swift`・`RepositoryGroupView.swift`・`DisclosureButton.swift`（ホバーのボタンの重ね方の共有）、`Mewbell/UI/OpenWebNotificationsButton.swift`、`Mewbell/UI/NotificationListView.swift`（`ThreadListActions`）、`Mewbell/Polling/NotificationStore.swift`（すべて Done の入口）、`Mewbell/App/MenuBarContentView.swift`（つなぎ込み）、テスト
- トークン: 触れる。送るリクエストの種類は増えないが、1 回の操作で送る数が最大で一覧の件数（500 件）まで増える。トークンの取得・保持の仕方は変えず、今までどおりメモリ上の actor にだけ持ち、永続化しない
- ネットワーク: 触れる。新しい経路は作らず、既存の `AccountPoller.perform(_:)` と `GitHubAPIClient` の Done のメソッドを通す（オリジン検査・リダイレクトの拒否・キャッシュなしはそのまま掛かる）
- URL を開く処理: 触れない（Web の通知一覧のボタンは記号と大きさを変えるだけで、開く URL と検証は変えない）
- gh サブプロセス: 触れない
- 永続化: しない。確認の表示の状態は View にだけ持つ
- 取り消し: Done は GitHub の側で取り消せないので、2 段階の確認にする
