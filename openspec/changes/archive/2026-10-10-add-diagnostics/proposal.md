# Proposal

## Why

M4 の前半と `add-settings` で、通知を読み、片付け、振る舞いを設定で変えられるようになった。ただ、うまく動かないときにユーザーが原因を探す手段がない。Mewbell がどの gh をどの設定ディレクトリで使っているのか、そのバージョン、アカウントごとの最後の取得と次の取得の時刻は、ログ（`log show`）を読まないと分からない。既読・Done・すべて既読が失敗してもログに書くだけなので、ユーザーには、消えたスレッドが次の取得で一覧に戻ってくるようにしか見えない。未読が 500 件（50 件 × 10 ページ）を超えるアカウントでは、それより古い未読を取得しないが、そのことが画面に出ない。そのため「すべて既読」の確認の `Mark 500 as read?` が、実際に既読になる件数より少なく見える。

マイルストーン: M4「設定と操作」の最後。M4 は 3 つの change に分けた: `add-thread-actions`（済み）、`add-settings`（済み）、この `add-diagnostics`。`add-settings` の proposal で「扱わないもの」に挙げた 3 つをこの change で扱う。

## What Changes

- 設定ウィンドウに 4 つ目のタブ「Diagnostics」を足す。中身は次のとおりで、開いている間に状態が変わったら表示もすぐ変える
  - gh: 使っている gh の実体のパスと見つけ方（設定の上書き、`/opt/homebrew/bin` などの既定の場所、ログインシェル）、gh のバージョン、gh の設定ディレクトリとその決め方（設定の上書き、`GH_CONFIG_DIR`、`XDG_CONFIG_HOME`、既定）、全体の状態
  - アカウントごと: トークンの状態（トークンそのものは出さない）、取得の状態、最後に取得できた時刻、次の取得の予定時刻、使っているポーリングの間隔（`X-Poll-Interval`）、トークンのスコープの名前（`X-OAuth-Scopes`）、「参加しているスレッドだけにする」の値、一覧の件数と 500 件で打ち切ったかどうか、最後の取得の失敗の種類、最後の操作（既読・Done・すべて既読）の失敗の種類と時刻
  - 「Copy」ボタンで、同じ内容をテキストでクリップボードにコピーする（不具合の報告に貼れるように）。API の URL とレート制限の残りは出さない
- 既読・Done・すべて既読の失敗を、ポップオーバーのそのアカウントの区画に 1 行で出す（例: 「既読にできなかった。次の取得で一覧に戻る」）。表示は、そのアカウントの次の取得が成功したら消す。失敗の理由は、認証エラー・レート制限・それ以外の 3 つに分けるだけにし、API のエラーボディや状態コードの説明文は出さない
- 通知の取得を 10 ページで打ち切ったこと（10 ページ目にも `rel="next"` があったこと）を、取得の状態として持つ。ポップオーバーのそのアカウントの区画に「新しい 500 件だけを表示している」ことを出す
- 打ち切ったアカウントの「すべて既読」は、「参加しているスレッドだけにする」と同じく、確認の表示を件数なしの `Mark all as read?` にし、一覧に出ていない古い未読も既読になることをツールチップとアクセシビリティのラベルで伝える（GitHub は通知を `updated_at` の新しい順に返すので、取得しなかった未読はすべて `last_read_at` 以前になり、一緒に既読になる）
- メニューバーの未読バッジは変えない（100 件以上は `99+` なので、500 件で打ち切っても表示は同じ）
- README の現状の説明を更新する

この change では扱わないもの:

- Diagnostics の内容をファイルに書き出すこと、ログ（`log show`）を集めて添付すること
- 操作の失敗の再送や、操作の 401 のあとのトークンの取り直し（今と同じく、次の取得でスレッドが一覧に戻るだけ）
- 500 件を超えて取得するための設定（ページの上限は変えない）

## Capabilities

### New Capabilities

- `diagnostics`: Diagnostics タブに出す項目、出してはならないもの（トークン、API の URL、gh や API の生の出力）、表示をすぐ更新すること、コピーの中身。設定ウィンドウの 1 タブだが、gh-cli・accounts・polling の状態を横断して読み出す約束なので、settings に混ぜず、`openspec/config.yaml` が挙げる `diagnostics` の capability として新設する

### Modified Capabilities

- `settings`: 「設定ウィンドウを開く」のタブを General、Accounts、gh、Diagnostics の 4 つにする
- `gh-cli`: 検出の結果（gh の実体のパスと見つけ方、バージョン、設定ディレクトリと決め方）を Diagnostics のために持つことを足す（ADDED）。検出そのものの順序や検証は変えない
- `github-api`: 「通知の取得」で、10 ページで打ち切ったかどうかを結果に含める
- `polling`: 「取得の状態」に、打ち切ったかどうか、次の取得の予定時刻、ポーリングの間隔、スコープ、最後の取得の失敗の種類を足す。操作の失敗を記録して、次の取得が成功したら消すことを足す（ADDED）
- `ui`: 「通知の取得の状態の表示」に打ち切りの表示を足す。「すべて既読のボタン」で、打ち切ったアカウントの確認の表示を `Mark all as read?` にする。操作の失敗の表示を足す（ADDED）

## Impact

- コード: `Mewbell/GitHubAPI/GitHubAPIClient.swift`（打ち切りの印）、`Mewbell/Polling/`（`FeedState` に打ち切り・診断の値・操作の失敗を足す、`AccountPoller` で記録する）、`Mewbell/GhCLI/`（`GhLocator` が見つけ方を返す、設定ディレクトリの決め方を返す）、`Mewbell/Accounts/AccountDiscovery.swift` と `AccountStore.swift`（検出の結果を UI に渡す）、新しい `Mewbell/Diagnostics/`（表示とコピーの中身を作る型）、`Mewbell/UI/`（Diagnostics タブ、区画の打ち切りと操作の失敗の表示、`MarkAllReadButton`）、`Mewbell/App/`（設定ウィンドウに `NotificationStore` を渡す）、テスト、README
- 依存: 外部のパッケージは足さない。クリップボードには AppKit の `NSPasteboard` を使う
- トークン: 取得・保持・送信・破棄の仕方は変えない（今までどおりメモリ上の actor にだけ持ち、永続化しない）。Diagnostics にはトークンの状態（取得中・使える・取れない・無効）だけを出し、トークンの値・長さ・接頭辞は出さない。コピーするテキストはトークンらしい文字列を伏せ字にしてから渡す
- gh サブプロセス: 触れる。実行するコマンド・引数・環境・検証は変えない。`gh --version` の出力から読んだバージョンの数字だけを持ち、gh の標準出力・標準エラー出力はそのまま表示もコピーもしない
- ネットワーク: 触れる。送るリクエスト・送り先・オリジン検査・リダイレクトの拒否・キャッシュなしは変えない。レスポンスから打ち切りの有無、`X-Poll-Interval`、`X-OAuth-Scopes` のスコープ名、状態コードの数字を状態に持つ。レスポンスボディやヘッダーの生の値は表示しない
- URL を開く処理: 触れない
- 永続化: 増やさない。診断の値と操作の失敗はメモリにだけ持ち、アプリを終了したら残さない。UserDefaults に新しいキーは足さない
