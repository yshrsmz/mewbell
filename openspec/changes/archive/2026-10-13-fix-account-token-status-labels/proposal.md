# Proposal

## Why

ポップオーバーのアカウントの見出しにあるトークンの状態のアイコン（`AccountSectionView` の `tokenIcon`）には、ツールチップ（`.help`）だけを付けていて、VoiceOver の名前を付けていない。VoiceOver では記号の既定の名前（警告の三角など）が読まれ、トークンの状態が分からない。特に「止まっている」（トークンは取れたが、スコープ不足や認証エラーで取得が止まった）と「トークンを取れない」は同じ記号（`exclamationmark.triangle.fill`、黄色）なので、見た目でも読み上げでも区別できない。トークンを取得中の印（`ProgressView`）には、ツールチップも名前も無い。

ui の Requirement「一覧の折りたたみ」は、折りたたみの操作が見出しの中身（トークンの状態を含む）の読み上げを上書きしないことを求めているが、そもそもトークンの状態に読み上げの名前が無い。スレッドの行の状態のアイコンは、`ThreadIcon` が記号・色・名前を決めて VoiceOver で読ませている（ui「スレッドの行の状態のアイコン」）ので、見出しのアイコンもそれに揃える。

この change は、M4（設定と操作）の UI のアクセシビリティの修正にあたる（M5 の v0.1.0 の公開後）。

## What Changes

- トークンの状態のアイコンの記号・色・名前を、状態（トークンの状態と、取得が止まっているか）から決める小さな値型を `UI/` に置く。`ThreadIcon` と同じ形にする
- アイコンには、その名前を VoiceOver の名前とツールチップの両方として、状態の分岐の外で 1 回だけ付ける。取得中の印にも名前とツールチップを付ける
- 名前は今のツールチップの文言（`Ready`、`Stopped`、`No token`、`Disabled`）をそのまま使い、取得中には `Getting token` を足す。「止まっている」と「トークンを取れない」は名前で区別する
- `IconColumnTests` のトークンの状態の記号を、テストに書き並べる代わりに値型から集める
- ui に Requirement「アカウントの見出しのトークンの状態の読み上げ」を足す（ADDED）

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `ui`: Requirement「アカウントの見出しのトークンの状態の読み上げ」を足す（ADDED）。記号・色・見出しの並びは変えない

## Impact

- 変わるコード: `Mewbell/UI/`（`AccountSectionView.swift` と、値型を置くファイル）、`MewbellTests/`（`IconColumnTests.swift` と値型のテスト）
- 見た目: 取得中の印にツールチップが付くことだけが変わる。記号・色・配置は変えない
- 読み上げ: アカウントの見出しで、トークンの状態が名前で読まれるようになる
- トークン: 扱わない。トークンの状態（列挙値）を表示に使うだけで、トークンの値には触れない。何も永続化しない
- gh サブプロセス: 触れない
- ネットワーク: 触れない
- URL を開く処理: 触れない
- 外部依存: 追加しない
