# Design

## Context

ポップオーバーの一覧では、次の 3 つを同じ幅の列（アイコンの列）の中央に置き、見出しと行の字下げを揃えている。

- スレッドの行の種類のアイコン（`ThreadRow`。記号は `ThreadIcon` が種類と状態から決め、書体は付けない＝本文の 13pt）
- 見出しの山形（`DisclosureChevron`。`chevron.right` を `.subheadline` の semibold で描き、開くと 90° 回す）
- アカウントの見出しのトークンの状態のアイコン（`AccountSectionView` の `tokenIcon`。書体は付けない。取得中は `ProgressView`）

列の幅は `ListLayout.chevronWidth`（16pt）で、見出しの下の中身の字下げ（`contentIndent`）は列の幅と間隔（6pt）の和にしている。記号の配置の幅（`NSHostingView` の `fittingSize`）は記号ごとに違い、Discussion の `bubble.left.and.bubble.right` は倍率 1 で 23pt、倍率 2 で 22pt ある（ほかの実測は proposal）。列より広い記号は列の外にはみ出し、スレッドの行では行の `.mask` の外に出た左端が約 1pt 切れていた。

## Goals / Non-Goals

**Goals:**

- 列に置くどの記号も、倍率 1 と 2 のどちらの画面でも、マウスを載せているときも、欠けずに出るようにする
- 列の揃い（3 つのアイコンが同じ幅の列の中央に並ぶこと）を保つ
- 記号や状態が増えたときに、列からはみ出すことをテストで気づけるようにする

**Non-Goals:**

- トークンの状態のアイコンの VoiceOver の名前（今は `.help` だけで、アクセシビリティの名前を付けていない）
- 見出しのベースラインの揃え（アイコンと見出しの文字を、中央ではなくベースラインで揃えること）
- 列に置く記号の部品化（記号と書体を 1 か所にまとめ、View とテストが同じものを参照すること）

これらは別の change で扱う。

## Decisions

### D1: 記号は縮めない

記号は書体で決まる大きさのまま描き、列に収めるために縮めない。縮める方法（`.imageScale(.small)`、小さい書体、`.resizable()` と `.frame`）は、次の理由で採らない。

- ui の Requirement「ポップオーバーの文字の読みやすさ」は、書体で大きさが決まるアイコンを 11pt より小さい書体で描くことを禁じている。Discussion の記号を 16pt に収めるには、この下限を割る
- SF Symbols は、記号を並ぶ文字の書体に合わせて描き、記号ごとの幅の違いは置き場所の側で吸収するのが慣用になっている。記号ごとに大きさを変えると、行ごとに記号の太さと高さがばらつく

### D2: 列の幅は配置の枠を基準に 24pt にする

列の幅は、列に置くどの記号の配置の枠（`fittingSize`）も、倍率 1 と 2 のどちらでも収まる幅にする。最も広いのは倍率 1 の Discussion の 23pt なので、24pt にする。`ListLayout.chevronWidth` は、山形のほかにトークンの状態とスレッドの行の種類のアイコンも置く列の幅なので、`ListLayout.iconColumnWidth` に改名する。`contentIndent` は今の式（列の幅と間隔の和）のままにし、30pt になる。

採らなかった案:

- 描かれる部分（記号の画素）を基準に 20〜22pt にする: 配置の枠のうち記号の左右の透明な余白に頼ることになる。どこまで余白があるかは記号と倍率で変わり、テストで確かめるには画素を測るか、配置の幅に許容幅を足す必要がある
- 行の `.mask` を広げるだけにする: 記号が欠けなくはなるが、列からはみ出したままで、ほかの行の記号や見出しの山形との列の揃いは良くならない
- Discussion の記号を `bubble.left` にする: 列に収まるが、GitHub の Discussion の記号（吹き出しが 2 つ）から離れる。ユーザーが採らなかった

代償:

- 件名とアカウントの見出しに使える幅が、main より 16pt 狭くなる（スレッドの件名は、見出しの下の字下げと行の列の 2 つ分。アカウントの見出しは、山形とトークンの状態の列の 2 つ分）。ポップオーバーの幅（380pt）は変えないので、長い件名は 2 行で省略されやすくなり、見出しのホスト名は早めに省略される
- どの行も、記号と件名の間が約 4pt 空く。列の中央に置くので、多くの記号（配置の幅が 15〜17pt）では右の空きが広がる

### D3: テストの測り方

新しいファイル `MewbellTests/IconColumnTests.swift` で、列に置く記号が列に収まることを確かめる。

- 記号の `Image(systemName:)` を `NSHostingView` に入れ、`.environment(\.displayScale, s)` で倍率を 1 と 2 に固定して `fittingSize` を測る。配置の幅は倍率で 1pt ほど変わる（Discussion は倍率 1 のほうが、`exclamationmark.triangle.fill` は倍率 2 のほうが広い）ので、両方で測る。失敗のメッセージには記号名・倍率・大きさを出す
- 書体は View と同じにする。スレッドの行の種類のアイコンとトークンの状態のアイコンは書体を付けずに、山形は `.subheadline` の semibold で測る。山形は 90° 回るので、幅と高さの大きいほうを比べる。`rotationEffect` は配置の枠を変えないので、測るときには回さない
- スレッドの行の記号は、`ThreadIcon(kind:state:)` に種類と状態（分からないときの nil を含む）のすべての組を渡して集める。種類と状態の一覧はテストに書き並べ、そのすぐ隣に `default` の無い網羅的な `switch` を書いた関数を置く。`SubjectKind` か `SubjectState` に case を足すと、そこでコンパイルが止まり、一覧に足すことに気づける。`CaseIterable` にすれば一覧が要らなくなるが、`SubjectKind` は `other(String)` を持つので合成されず、API の層（`Mewbell/GitHubAPI/`）に手を入れることになる。この change は表示の不具合の修正なので、新しい型も API の層の変更も足さない
- トークンの状態のアイコンの記号名と山形の書体・記号名は、View とテストの両方に書く。View の側の記号や書体を変えたときにテストを直し忘れるおそれは残るが、まとめるには記号の部品化（Non-Goals）が要る。記号を変えるのは見た目の変更で、そのときは列に収まるかを見直すことになるので、この重複は許容する

確かめたこと: 列を一時的に 16pt にすると `bubble.left.and.bubble.right`・`point.3.connected.trianglepath.dotted`・`tag`（倍率 1 と 2）と `exclamationmark.triangle.fill`（倍率 2）で落ち、22pt にすると倍率 1 の `bubble.left.and.bubble.right` で落ちた（tasks 2.2）。

### スレッドと actor の境界

本体の actor と `@MainActor` の境界は変えない。View の変更は定数の名前と値だけ。テストは `NSHostingView` を作るので、テストの型を `@MainActor` にする。

### テストでの差し替え

ネットワークと gh サブプロセスには触れないので、差し替えるものは無い。テストは本物の SwiftUI の配置で記号を測る。

## セキュリティ

トークン・gh サブプロセス・ネットワーク・URL を開く処理のいずれにも触れない。表示する項目と操作は変えず、列の幅だけを変える。トークンの流れは変わらない。`.claude/rules/security.md` の項目で、この change で新しく満たすものは無い。

## Risks / Trade-offs

- [件名とアカウントの見出しに使える幅が 16pt 狭くなる] → ポップオーバーの幅は 380pt のままで、件名は 2 行まで、見出しはホスト名から省略する決まり（ui「ポップオーバーの文字の読みやすさ」）はそのまま働く。手元の画面で、長い件名と長いホスト名の見え方を確かめる（tasks 3.2）
- [配置の枠は OS の版で変わりうる] → 測る値は OS の SF Symbols の版に依存する。版が変わって記号が広がったときは、`IconColumnTests` が落ちて気づける
