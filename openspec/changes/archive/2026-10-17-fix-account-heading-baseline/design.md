# Design

## Context

見出しは 2 段の `HStack` でできていて、どちらも既定の中央揃えで並べている。

```
DisclosureButton の HStack（中央揃え）
+--------+------------------------------------------------------+-------+
| 山形   | label（AccountHeadingView の title。中央揃えの HStack）| 件数  |
|        | tokenIcon / ユーザー名 / active / ホスト名 / 参加の印 |       |
+--------+------------------------------------------------------+-------+
```

- `DisclosureButton` が山形・`label`・折りたたんだときの件数（`CollapsedCount`）を並べる。畳めないとき（`isCollapsible == false`）も、山形を `hidden()` にした同じ並びにする
- アカウントの見出しの `label` は `title` で、トークンの状態のアイコン（`tokenIcon`。取得中は `ProgressView`）と文字が入っている。リポジトリの見出しの `label` はリポジトリ名だけ
- ずれの実測は proposal の Why にある。文字どうしは 1.5pt ずれていて、山形とトークンの状態のアイコンは文字の中心から 0.5pt 以内に揃っている
- 件数は `title` の外（`DisclosureButton` の外側の `HStack`）にある。そのため `title` の中だけをベースラインで揃えると、畳んだときに件数がアクティブの印やホスト名とずれる

## Goals / Non-Goals

**Goals:**

- 見出しの文字と件数をベースラインで揃え、山形とトークンの状態のアイコンは縦の中央に残す（spec の「見出しの文字のベースライン」）
- 畳めるときと畳めないときで、同じ並びにする

**Non-Goals:**

- アイコンをベースラインで揃えること（スレッドの行と同じ作りにすること）
- スレッドの行の揃え方の変更
- 見出しの書体・色・高さ・アイコンの列の幅の変更

## Decisions

### D1: 開閉のボタンに、山形の次に置くアイコンの引数を足す

`DisclosureButton` を、山形の次にアイコンを置ける形にする。アイコンは縦の中央に置き、`label` と件数だけを `.firstTextBaseline` の `HStack` に入れる。

```
HStack(spacing: ListLayout.spacing)              // 中央揃え
  DisclosureChevron                              // 中央
  icon                                           // 中央。アカウントの見出しだけ
  HStack(alignment: .firstTextBaseline, spacing: ListLayout.spacing)
    label                                        // 文字だけ
    CollapsedCount                               // 畳んでいて 1 件以上のとき
```

- 型は `DisclosureButton<Icon: View, Label: View>` にし、`@ViewBuilder let icon: Icon` を持たせる。アイコンを渡さない呼び出し（リポジトリの見出し、テスト）のために、`Icon == EmptyView` の extension に `icon` を取らないイニシャライザを置く。SwiftUI の標準の View（`Button`・`Label` など）が、省ける中身を制約付きの extension のイニシャライザで省くのと同じ形にする
- アイコンの幅は呼び出し側が決める（今と同じく `tokenIcon` に `.frame(width: ListLayout.iconColumnWidth)` を付ける）。`DisclosureButton` はアイコンの列の幅を知らなくてよい
- アカウントの見出しは、`tokenIcon` を `title` から外して `icon` に渡す。`title` は文字だけの `HStack(alignment: .firstTextBaseline)` にする
- 畳めないときの並びも、同じ 3 段（山形、アイコン、ベースラインの `HStack`）にする。`accessibilityElement(children: .combine)` で 1 つの要素にまとめるのは今のまま。読み上げの順（トークンの状態の名前、ユーザー名、…）も変わらない

原則: A9（型・抽象・部品は要件かテストに要るときだけ足す）。新しい型やファイルは足さず、既存の部品に引数を 1 つ足すだけにする。この引数は、spec の「アイコンは中央、文字はベースライン」を満たすために要る。A16（押せる要素の見た目）と A17（書体はテキストスタイル）は今のまま守る。

採らなかった案:

- `label` の中で入れ子にする（外側は「山形は中央、`label` と件数はベースライン」、アカウントの `label` は「アイコンは中央、文字はベースライン」）: 引数は増えない。しかし、入れ子の中央揃えの `HStack` を外側のベースラインの `HStack` に入れたとき、そのベースラインがどの子から取られるかは SwiftUI の内部の決め方に依存する。アイコンの記号（`Image(systemName:)` もベースラインを持つ）や `ProgressView` に左右されるおそれがある。ユーザーが採らなかった
- `title` の中だけをベースラインにする: 畳んだときに件数がアクティブの印やホスト名と約 1.5pt ずれる。ユーザーが採らなかった
- `tokenIcon` に `alignmentGuide(.firstTextBaseline)` を付けて、ベースラインの `HStack` の中で中央に寄せる: 文字の中心とベースラインの距離は書体の寸法で決まる。値を書くと A17 に反し、文字の大きさの設定にも追従しない

### D2: 山形とアイコンは中央に残す

山形とトークンの状態のアイコンは、ベースラインで揃えずに縦の中央に置く。次の 3 つが理由。

- 実測で、文字の中心から 0.5pt 以内に揃っている
- 取得中の `ProgressView` は文字のベースラインを持たない。ベースラインで揃えると下端がベースラインに付き、記号の状態と取得中の間を切り替えるたびに上下に動く
- 「見出しの押せる範囲の高さ」の Scenario（山形・トークンの状態・ユーザー名は塗りの縦の中央に出る）と合う

スレッドの行はアイコンもベースラインで揃えているが、それは件名が 2 行になる行で、アイコンを 1 行目に付けるため。見出しは 1 行なので、事情が違う。

### D3: テスト

A12 に従い、揃い方（ベースラインの位置）は単体テストにしない。`NSHostingView` からはベースラインの位置を取れず、書体の見た目は手元で確かめる項目にしている。代わりに次を行う。

- `DisclosureButtonHeightTests` に、アイコンを渡す場合を足す。アカウントの見出しと同じ組み合わせ（`.headline` の文字と `.subheadline` の文字を並べ、記号のアイコンを渡す）でも、見出しの高さが `ListLayout.headingHeight` のままであることを確かめる。並びを変えて見出しが高くなる不具合を拾う
- `DisclosureButtonCountTests` の型の書き方を、引数が 2 つの generic に合わせて直す
- 手元の確認では、proposal の Why と同じ方法（`bash scripts/run.sh` で起動し、ポップオーバーの範囲だけを撮って、文字の下端とアイコンの中心の画素を測る）で、ベースラインが揃い、アイコンが中央に残ることを確かめる。取得中の印と、畳んだときの件数も見る

### docs/architecture.md への追記

この change の判断（見出しの文字はベースライン、アイコンは中央）は、表示の振る舞いとして spec の「見出しの文字のベースライン」に書く。コードの構造の原則ではないので、docs/architecture.md には足さない。消す・改名する型・メンバー・ファイルも無い（`DisclosureButton` の名前は変わらない）。

### スレッドと actor の境界

変えない。変わるのは `@MainActor` の View の並びだけ。

### テストでの差し替え

ネットワークと gh サブプロセスには触れないので、差し替えるものは無い。

## セキュリティ

トークン・gh サブプロセス・ネットワーク・URL を開く処理のいずれにも触れない。見出しに出す項目と操作は変えず、並び方だけを変える。トークンの流れは変わらない。`.claude/rules/security.md` の項目で、この change で新しく満たすものは無い。

## Risks / Trade-offs

- [`OneLineText` の中の `ViewThatFits` と `ZStack` が、ベースラインを外へ伝えないおそれがある] → 伝わらなければ、ユーザー名やホスト名の下端が揃わず、手元の測定で分かる。そのときは `OneLineText` の中で伝わる形を探し、変えたものを design に足す
- [アイコンを `label` の外に出すと、アカウントの見出しのツールチップやアクセシビリティの付き方が変わる] → `tokenIcon` の `.help` と `.accessibilityLabel` はアイコン自身に付いているので、置き場所を変えても残る。読み上げは手元の VoiceOver で確かめる
- [リポジトリの見出しの見た目が変わる] → 文字の大きさが揃っているので、ベースラインで揃えても位置はほぼ変わらない見込み。手元の測定で、山形とリポジトリ名の位置が今と変わらないことを確かめる
