# Spec Delta

## ADDED Requirements

### Requirement: スレッドの既読化

ユーザーがスレッドを開いたとき（ui「通知のスレッドを開く」、notifications「通知のクリック」）、Mewbell はそのスレッドをアカウントの未読の一覧からすぐに外し（SHALL）、そのアカウントのトークンで既読化のリクエスト（github-api「スレッドの既読化のリクエスト」）を送らなければならない（SHALL）。既読化のリクエストは、そのアカウントの取得の間隔や待ち時間（「ポーリングの間隔」「失敗したときの待ち方」）を変えてはならず（MUST NOT）、取得と並行して送ってよい（MAY）。既読化の結果にかかわらず、そのアカウントの次の取得は `If-Modified-Since` を付けない取得にしなければならない（MUST。既読化が `304` に隠れないように、また失敗したスレッドが次の取得で一覧に戻るように）。外したスレッドは、既読化のリクエストが終わった後に送った取得の結果が出るまで、一覧に戻してはならない（MUST NOT。既読化より前に送った取得の結果に含まれていても戻さない）。アカウントが「スコープ不足」か「認証エラー」で止まっているとき、またはトークンをメモリに持っていないときは、既読化のリクエストを送らなくてよい（MAY）。

#### Scenario: 一覧のスレッドを既読にする

- **GIVEN** `github.com/alice` の一覧に、スレッド `123` と `456` がある
- **WHEN** ユーザーがスレッド `123` を開く
- **THEN** `123` はすぐに一覧から消え、`456` は残る
- **AND** `PATCH /notifications/threads/123` が送られる
- **AND** `alice` の次の取得は、予定の時刻に `If-Modified-Since` を付けずに送られる

#### Scenario: 既読化が失敗する

- **GIVEN** ユーザーがスレッド `123` を開き、既読化のリクエストが通信の失敗になった
- **WHEN** 次の取得が成功し、`123` が未読のまま返る
- **THEN** `123` が一覧に戻る

#### Scenario: 取得中に既読にする

- **GIVEN** `alice` の取得のリクエストを送っている最中
- **WHEN** ユーザーがスレッド `123` を開く
- **THEN** 既読化のリクエストは取得の終わりを待たずに送られる
- **AND** その取得が `123` を含む結果を返しても、`123` は一覧に戻らない
