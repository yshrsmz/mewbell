# Proposal

## Why

M4 の前半までで、ポップオーバーの一覧から通知を読み、片付けられるようになった。ただ、振る舞いを変える手段がない。すべてのアカウントの通知が `participating=false` で取得され、macOS の通知も全アカウント分が音付きで出る。アプリはログイン時に起動しない。gh が見つからない環境や、gh の設定ディレクトリをシェルで変えている環境では、Finder から起動した Mewbell が gh や `hosts.yml` を見つけられず、ユーザーが直す手段がない。使わないアカウントだけを止めることもできない。

マイルストーン: M4「設定と操作」の後半。M4 は 3 つの change に分ける: `add-thread-actions`（済み）、この `add-settings`、`add-diagnostics`。この change では Settings シーンと、その画面で変える設定を扱う。Diagnostics の表示は `add-diagnostics` で扱う。

## What Changes

- Settings シーン（設定ウィンドウ）を足す。ポップオーバーの見出しの歯車ボタンと ⌘, で開き、開いたときは前面に出す。タブは General、Accounts、gh の 3 つ
- General: ログイン時に起動する（`SMAppService` で登録・解除し、状態はシステムから読む）、macOS の通知の音のオン・オフ
- Accounts: gh にログイン済みのアカウントごとに、次の 3 つを切り替える
  - 有効・無効: 無効にしたアカウントはポーリングを止め、メモリ上のトークンを捨て、`gh auth token` を実行せず、ポップオーバーの一覧・未読バッジ・macOS の通知から外す
  - 参加しているスレッドだけにする: 通知の取得に `participating=true` を付ける。切り替えたら、そのアカウントの一覧を最初から取り直し、取り直しで見えたスレッドは通知しない
  - macOS の通知のオン・オフ: オフのアカウントは一覧とバッジには出すが macOS の通知は出さず、出ている通知は取り下げる
- gh: gh の実行ファイルのパスと、gh の設定ディレクトリの上書き。設定ディレクトリを上書きしたときは、その中の `hosts.yml` を読み、gh の子プロセスにも `GH_CONFIG_DIR` として渡す。変えたら、持っているトークンをすべて捨ててアカウントを読み直す
- 参加しているスレッドだけにしたアカウントの「すべて既読」は、確認の表示を `Mark all as read?` にし、一覧に出ていない未読も既読になることをツールチップで伝える（`PUT /notifications` には絞り込みがないため）
- 設定は UserDefaults にだけ保存する。トークン、API の URL、gh の出力は保存しない。アカウントごとの設定は `<host>/<user>` をキーにし、gh からログアウトしたアカウントの設定も残す（ログインし直したときに戻るように）
- `SETUP.md` の M4 の行を `add-settings` と `add-diagnostics` の 2 行に分け、README の現状の説明を更新する

この change では扱わず、`add-diagnostics` に回すもの:

- Diagnostics の表示（gh のパスとバージョン、設定ディレクトリ、アカウントごとの取得の状態など）
- 既読・Done・すべて既読の失敗をユーザーに知らせる表示
- 通知の取得を 500 件（10 ページ）で打ち切ったことの表示

## Capabilities

### New Capabilities

- `settings`: 設定ウィンドウの構成と開き方、設定項目とその既定値、保存先（UserDefaults）と保存してはならないもの、変更をすぐ反映すること、ログイン時起動の登録。設定は gh-cli・accounts・polling・notifications・ui のすべてにまたがるので、保存と既定値の約束を 1 か所にまとめるために新設する。各 capability での振る舞いの変化は、それぞれの spec に書く

### Modified Capabilities

- `gh-cli`: 「gh 実行ファイルの検出」の上書きパスを設定から渡す。「hosts.yml の場所と読み取り」の候補の先頭に設定の上書きを足し、そのときは gh の子プロセスに `GH_CONFIG_DIR` を渡す。上書きの値の検証を足す
- `accounts`: 「アカウントごとの状態」に「無効」を足す。「読み直しのタイミング」で、無効なアカウントの `gh auth token` を実行しない。「不要になったトークンの破棄」に、無効にしたときと、gh の設定ディレクトリの上書きを変えたときを足す
- `github-api`: 「通知の取得」の `participating` を、アカウントの設定に従わせる
- `polling`: 「ポーリングの開始と停止」で、無効なアカウントのポーリングを止める。参加しているスレッドだけにする設定を変えたら、そのアカウントの取得を最初からやり直す
- `notifications`: 「新着の通知」に、アカウントごとの通知のオフと、最初の取得として扱う場面（参加しているスレッドだけにする設定を変えた後、有効にし直した後）を足す。「通知の中身」で音を設定に従わせる。「通知の取り下げ」に、無効にしたときと通知をオフにしたときを足す
- `ui`: 「ポップオーバーの表示」に設定を開くボタンを足す。「アカウント一覧の表示」「未読バッジ」で無効なアカウントを外し、すべて無効のときの表示を足す。「案内画面」に、上書きした gh のパスや設定ディレクトリが使えないときの案内を足す。「すべて既読のボタン」に、参加しているスレッドだけにしたアカウントの確認の表示を足す

## Impact

- コード: `Mewbell/App/`（Settings シーン、設定を開く処理、`AppDelegate` の配線）、新しい `Mewbell/Settings/`（設定の保存、ログイン時起動）、`Mewbell/UI/`（設定画面、歯車ボタン、無効なアカウントの扱い、すべて既読の表示）、`Mewbell/Accounts/AccountDiscovery.swift` と `AccountStore.swift`（読み直しごとに上書きを読む、無効なアカウントを飛ばす）、`Mewbell/GhCLI/`（設定ディレクトリの上書きと検証、子プロセスの環境）、`Mewbell/Polling/NotificationStore.swift`（無効化と `participating` の切替でポーラーを止める・作り直す）、`Mewbell/Notifications/`（アカウントごとの通知のオフ、音）、テスト、`SETUP.md`、`README.md`
- 依存: `ServiceManagement`（OS のフレームワーク）を使う。外部のパッケージは足さない
- トークン: 触れる。無効にしたアカウントと、設定ディレクトリの上書きを変えたときの全アカウントのトークンを、メモリからすぐに捨てる。トークンの取得・保持の仕方は変えず、今までどおりメモリ上の actor にだけ持ち、永続化しない。設定（UserDefaults）にはトークンを書かない
- gh サブプロセス: 触れる。上書きした gh のパスも既存の検証（通常ファイル、実行可能、他人が書き込めない）を通す。設定ディレクトリを上書きしたときは、子プロセスの環境に `GH_CONFIG_DIR` を入れる。取り除く環境変数（`GH_TOKEN` など）は変えない
- ネットワーク: 触れる。通知の取得の `participating` の値がアカウントごとに変わる。送り先・オリジン検査・リダイレクトの拒否・キャッシュなしは変えない
- URL を開く処理: 触れる。ログイン項目の承認が要るときに、システム設定のログイン項目の画面を開く（`SMAppService.openSystemSettingsLoginItems()`）。GitHub の Web の URL を開く処理は変えない
- 永続化: 設定を UserDefaults に保存する。保存するのは真偽値、アカウントの識別子（`<host>/<user>`）、ファイルのパスだけ
