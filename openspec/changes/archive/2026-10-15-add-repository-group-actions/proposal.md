# Proposal

## Why

今の一覧で片付ける操作は、スレッド 1 件ずつの「既読にする」「Done にする」と、アカウント全体の「すべて既読」しかない。bot の Pull request や CI の通知のように、1 つのリポジトリにまとまって届く通知を片付けるには、行を 1 件ずつ操作するか、アカウントのほかのリポジトリまで巻き込んで「すべて既読」にするしかない。Done はアカウント単位の操作も無い。

マイルストーン: M4「設定と操作」の追補。`add-thread-actions` で入れたポップオーバーの一覧の操作を、リポジトリのグループにも広げる。

## What Changes

- リポジトリの見出しにマウスを載せると、右端に「既読にする」と「Done にする」のボタンが出る。同じ 2 つを見出しのコンテキストメニュー（右クリック）と、VoiceOver の操作にも出す。どれもブラウザでは開かない
- 対象は、押したときにそのグループに出していたスレッドだけにする。折りたたんだグループでも同じ。一覧に出ていない未読（「参加しているスレッドだけにする」で外れたもの、500 件で打ち切ったもの）は対象にしない
- 「既読にする」は確認せずにすぐ行う。グループのスレッドを 1 件ずつ既存の既読化（`PATCH /notifications/threads/{id}`）にかける。`PUT /repos/{owner}/{repo}/notifications` は使わない（一覧に出ていない未読まで既読にし、Done と対象がずれるため）
- 「Done にする」は取り消せず複数のスレッドに効くので、「すべて既読」のボタンと同じ 2 段階の確認にする。1 回目でボタンを確認の表示（`Mark N as done?`）に変え、5 秒以内にもう一度押したときだけ、グループのスレッドを 1 件ずつ Done（`DELETE /notifications/threads/{id}`）にする。コンテキストメニューと VoiceOver の操作で選んだときも、すぐには行わず、見出しを同じ確認の表示にする
- グループのスレッドへのリクエストは、1 件ずつ順に送る。認証エラーかレート制限になったら、残りは送らない（残りのスレッドは次の取得で一覧に戻る）
- 失敗の知らせは、グループの操作 1 回につき 1 つにまとめる

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `polling`: リポジトリのグループのスレッドをまとめて既読・Done にする要件を足す（対象の決め方、1 件ずつ順に送ること、認証エラーとレート制限で残りを送らないこと、失敗の記録をまとめること）。各スレッドの一覧からの外し方・戻し方・通知の取り下げは、既存の「スレッドの既読化」「スレッドの Done」に従わせる
- `ui`: リポジトリの見出しの操作（ホバーのボタン、コンテキストメニュー、VoiceOver の操作、Done の 2 段階の確認）の要件を足す。「ポップオーバーの押せる要素のホバーの反応」に、リポジトリの見出しのボタンと、ボタンに載せている間も見出しを塗り続けることを足す。「ポップオーバーの文字の読みやすさ」で、アクセントカラーと省略しない文に、リポジトリの Done の確認の文を足す

`github-api` は変えない（既存の `PATCH` と `DELETE` をそのまま使う）。`notifications` の「通知の取り下げ」は、グループの各スレッドが「スレッドの既読化」「スレッドの Done」を通るので、そのまま効く。

## Impact

- コード: `Mewbell/Polling/AccountPoller+ThreadActions.swift`（グループの操作）、`Mewbell/Polling/NotificationStore.swift`（グループの操作の入口）、`Mewbell/UI/RepositoryGroupView.swift`・`ThreadRow.swift`・`DisclosureButton.swift`・`AccountSectionView.swift`（見出しの操作、確認のボタンの共有）、`Mewbell/App/MenuBarContentView.swift`（操作のつなぎ込み）、テスト
- トークン: 触れる。送るリクエストの種類は増えないが、1 回の操作で送る数が増える。トークンの取得・保持の仕方は変えず、今までどおりメモリ上の actor にだけ持ち、永続化しない
- ネットワーク: 触れる。新しい経路は作らず、既存の `GitHubAPIClient` の既読化と Done のメソッドを通す（オリジン検査・リダイレクトの拒否・キャッシュなしはそのまま掛かる）
- URL を開く処理: 触れない（どの操作もブラウザを開かない）
- gh サブプロセス: 触れない
- 永続化: しない。確認の表示の状態は View にだけ持つ
- 取り消し: Done は GitHub の側で取り消せないので、2 段階の確認にする。既読は Web で未読に戻せるので確認しない
