# Proposal

## Why

GitHub の `GET /notifications` は、1 ページ目に `If-Modified-Since` を付けると、`200` のときもその時刻より後に `updated_at` が進んだスレッドだけを返す（`since` で絞ったのと同じ一覧になる）。手元の github.com のアカウントで確かめた: `all=true` で 50 件返る一覧が、`If-Modified-Since` を付けると 11 件になり、未読だけの一覧でも 3 件が 2 件になった。

Mewbell は、条件付きの取得の `200` も一覧をすべて取り直したものとして扱い、通知の一覧をまるごと置き換えている。仕様（polling「条件付きリクエスト」）にも「`If-Modified-Since` を付けた取得でも `200` なら一覧はすべて取り直される」と書いてある。このため次のことが起きる。

- 5 分ごとの条件なしの取得で一覧に入ったスレッドが、その後の条件付きの取得で新しい更新が届いたときに一覧から消え、次の条件なしの取得まで出てこない。Gitify と並べると、一覧が出たり消えたりして見える。
- 一覧から消えたスレッドの macOS の通知が取り下げられる。次の条件なしの取得で一覧に戻っても、`updated_at` が変わっていないので、通知は出し直されない。
- 条件付きの `200` でも「最後に `200` で全ページを取り終えた時刻」を進めるので、条件なしの取り直しがそこからさらに 5 分延びる。

## What Changes

- 条件付きの取得（1 ページ目に `If-Modified-Since` を付けた取得）の `200` は、更新されたスレッドだけの差分として扱う。今の一覧に、同じ ID のスレッドは差し替え、無いスレッドは足す。それ以外のスレッドは一覧に残す。
- 一覧から消えたスレッドを外すのは、条件なしの取得の `200` のときだけにする。macOS の通知の取り下げ、スレッドの状態とイベントの記録を捨てることも同じ。既読・Done・すべて既読で隠しているスレッドは、今までどおり条件付きの取得の結果からも取り除く。
- 条件なしで取り直す 5 分の間隔は、最後に条件なしの取得の `200` で全ページを取り終えた時刻から数える。
- 打ち切り（10 ページ）は、条件付きの `200` が打ち切られたときだけ「打ち切った」にし、そうでなければ前の値を保つ。
- `Last-Modified` は、今までどおり条件付きの `200` でも全ページを取り終えたら更新する。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `polling`: 「条件付きリクエスト」で、条件付きの `200` を差分として今の一覧に重ねることと、5 分の間隔を条件なしの `200` から数えることにする。誤った前提（条件付きの `200` は全件）を直す。「取得の状態」の打ち切りの値を、条件付きの `200` のときの扱いに合わせる。

notifications の「通知の取り下げ」は「一覧から消えたとき」に取り下げると書いていて、その文は変えない。一覧から消えるのが条件なしの取得のときだけになるので、取り下げもそのときだけになる。

## Impact

- マイルストーン: M2（通知取得）の保守の change。M3 の通知の取り下げにも効く。
- 変更するもの: `Mewbell/Polling/AccountPoller.swift`（条件付きの `200` の一覧の作り方、5 分の間隔の数え方、打ち切りの値）、差分を重ねる処理を置く Polling の型、そのテスト。`GitHubAPIClient` のリクエストとレスポンスの読み方は変えない。
- API の呼び出しの回数と間隔は変えない。
- トークン・gh サブプロセス・ネットワーク・URL を開く処理: いずれにも触れない。受け取った一覧をメモリの中でどう重ねるかだけを変える。トークンは今までどおりメモリにだけ持ち、永続化しない。
