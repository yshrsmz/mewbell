# Proposal

## Why

`@fission-ai/openspec` 1.14.1 から、要件の本文（`### Requirement:` の見出しの後から最初のシナリオの見出しまで）が 500 文字を超えると `openspec validate` が警告を出し、`--strict` では失敗するようになった。Mewbell の main specs は 9 件すべてがこの警告で `--strict` に失敗し（要件 52 件）、CI の `openspec validate --all --strict` が止まるため、1.14.1 への更新（Renovate の PR #56）を merge できない。

マイルストーン: どのマイルストーンにも属さない、仕様の書き方の整理。アプリの振る舞いは変えない。SETUP.md のマイルストーンの表には行を足さない。

## What Changes

- 本文が 500 文字を超える 52 件の要件を、1 つの要件が 1 つの振る舞いを述べる形に分ける。規範の文（MUST / SHALL / MUST NOT などを含む文）は言い換えずにそのまま残し、元の要件か、分けて足した要件の本文に置く
- 規範ではない例示や境界条件の説明は、その要件のシナリオへ移してよい。規範の文はシナリオへ移さない
- 分けた要件の名前は、元の要件に残した振る舞いが元の名前のまま読めるようにし、足した要件には中身を表す名前を付ける。他の spec・`docs/architecture.md`・コードのコメントが参照している要件名（`polling「取得の状態」` など）は、参照先の中身が移ったときだけ参照を直す
- 既存のシナリオは消さず、その振る舞いを述べる要件の下へ移す
- アーカイブで末尾に足される要件を、分けた元の要件のすぐ後ろへ並べ直す。並べ直しで要件とシナリオの中身が変わっていないことを確かめる
- 再発を防ぐため、`openspec/config.yaml` の specs のルールに、要件の本文を 500 文字以内にすることを足す
- アプリのコード、テスト、ビルドの設定は変えない（テストのコメントの要件名の参照だけを直す）

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

いずれも振る舞いは変えず、要件の分け方だけを変える（MODIFIED で元の要件の本文を短くし、ADDED で分けた要件を足す）。参照している中身が別の要件へ移ったため参照の名前だけを直す要件（polling「スレッドの Done」、ui「見出しの押せる範囲の高さ」）も MODIFIED に入る。ui「スレッドの行のイベント」は、参照の名前を直すと本文がちょうど 500 文字になるため、同じ規則で分ける。

- `accounts`: 「読み直しのタイミング」
- `diagnostics`: 「Diagnostics タブのアカウントの項目」
- `distribution`: 「バージョンとリリースの起点」「署名と entitlement の検査」「配布物」「CI の資格情報」「Homebrew tap の Cask の更新」「Homebrew Cask の中身」
- `gh-cli`: 「gh 実行ファイルの検出」「hosts.yml の場所と読み取り」「gh auth token の実行」「検出の結果の記録」
- `github-api`: 「通知の取得」「ステータスコードの扱い」「スレッドの既読化のリクエスト」「スレッドを Done にするリクエスト」「すべて既読のリクエスト」「スレッドのイベントの取得のリクエスト」「スレッドのイベントの決定」「リリースのタグの取得のリクエスト」「ワークフローの実行の検索のリクエスト」
- `notifications`: 「新着の通知」「通知の中身」「通知の取り下げ」「通知のクリック」
- `polling`: 「ポーリングの開始と停止」「条件付きリクエスト」「ポーリングの間隔」「失敗したときの待ち方」「取得の状態」「スレッドの既読化」「アカウントのすべて既読」「操作の失敗の記録」「スレッドのイベントの取得」「リポジトリのグループの既読化と Done」
- `settings`: 「設定項目と既定値」
- `ui`: 「アカウント一覧の表示」「案内画面」「再読み込みボタン」「通知の取得の状態の表示」「通知のスレッドを開く」「未読バッジ」「すべて既読のボタン」「操作の失敗の表示」「一覧の折りたたみ」「折りたたみの状態を覚える範囲」「Web の通知一覧を開く」「ポップオーバーの文字の読みやすさ」「スレッドの行の状態のアイコン」「アカウントの見出しのトークンの状態の読み上げ」「ポップオーバーの押せる要素のホバーの反応」「リポジトリの見出しの操作」

## Impact

- 仕様: `openspec/specs/` の 9 件。要件の数は増えるが、規範の文とシナリオの中身は変えない
- 設定: `openspec/config.yaml` の specs のルールに 1 行足す
- 文書: 参照先の中身が別の要件へ移ったときだけ、`openspec/specs/` の中の参照と `docs/architecture.md`・コードのコメントの参照を直す
- 依存: `@fission-ai/openspec` は 1.13.2 のまま。1.14.1 への更新は、この change を merge した後に PR #56 で行う
- コード・テスト: 変えない（テストのコメントの要件名の参照だけを直す）
- トークン: 触れない
- gh サブプロセス: 触れない
- ネットワーク: 触れない
- URL を開く処理: 触れない
- 永続化: しない（コードを変えないため）
