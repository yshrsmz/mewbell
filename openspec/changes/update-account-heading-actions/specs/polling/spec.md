## ADDED Requirements

### Requirement: アカウントのすべて Done

ユーザーがアカウントのスレッドをまとめて Done にしたとき（ui「すべて Done のボタン」）、Mewbell は、ユーザーが押したときにそのアカウントの一覧に表示していたスレッドだけを対象にしなければならない（SHALL）。押した後に届いたスレッドと、一覧に出ていない未読（「参加しているスレッドだけにする」で取得していないもの、500 件で打ち切って取得していないもの）を対象にしてはならない（MUST NOT）。対象が 0 件のときは何もしてはならない（MUST NOT）。

#### Scenario: すべて Done にする

- **GIVEN** `github.com/alice` の一覧に、`octo/app` のスレッド `1`（12:30）と `octo/lib` のスレッド `2`（12:00）がある
- **WHEN** ユーザーが `alice` のスレッドをすべて Done にする
- **THEN** `1` と `2` はすぐに一覧から消え、macOS の通知も取り下げられる
- **AND** `DELETE /notifications/threads/1` の結果が出てから `DELETE /notifications/threads/2` が送られる
- **AND** `PUT /notifications` は送られない
- **AND** `alice` の次の取得は、予定の時刻に `If-Modified-Since` を付けずに送られる

#### Scenario: 押した後に届いたスレッドは対象にしない

- **GIVEN** `alice` の一覧にスレッド `1` と `2` を表示している
- **WHEN** ユーザーがすべて Done にし、そのリクエストを送っている間の取得でスレッド `4` が届く
- **THEN** `4` は一覧に出て、`DELETE /notifications/threads/4` は送られない

### Requirement: アカウントのすべて Done のスレッドごとの扱い

対象のスレッドの一覧からの外し方、スレッドごとの扱い、失敗の記録、リクエストの順、認証エラーとレート制限で残りを送らないこと、途中で止まったときの扱いは、「リポジトリのグループの既読化と Done のスレッドごとの扱い」「リポジトリのグループの既読化と Done のリクエストの順」「リポジトリのグループの既読化と Done の途中で止まったとき」の Done と同じにしなければならない（MUST）。失敗は Done の失敗として記録し、1 回の操作で複数のスレッドが失敗しても、知らせる失敗は 1 つにしなければならない（MUST）。

#### Scenario: 途中でレート制限になる

- **GIVEN** `github.com/alice` の一覧にスレッド `1`、`2`、`3` がある
- **WHEN** ユーザーがすべて Done にし、`DELETE /notifications/threads/1` がレート制限の `403` を返す
- **THEN** `2` と `3` へのリクエストは送られない
- **AND** `alice` に、Done が「レート制限」で失敗したことが 1 つの知らせとして記録される
- **AND** その後に送った取得の結果で `1`、`2`、`3` が未読のまま返れば、一覧に戻る

#### Scenario: トークンが無い

- **GIVEN** `alice` の一覧にスレッド `1` と `2` があり、読み直しの途中で `alice` のトークンをメモリに持っていない
- **WHEN** ユーザーがすべて Done にする
- **THEN** リクエストは送られず、Done が「トークンを持っていない」で失敗したことが 1 つの知らせとして記録される
- **AND** `alice` の次の取得の結果で `1` と `2` が未読のまま返れば、一覧に戻る
