## ADDED Requirements

### Requirement: アカウントの見出しの操作

ポップオーバーの一覧のアカウントの見出しの操作（Web の通知一覧を開く、すべて既読、すべて Done）は、リポジトリの見出しの操作と同じく、見出しにマウスを載せている間だけ見出しの右端にボタンとして表示しなければならない（SHALL）。同じ操作を、見出しのコンテキストメニュー（右クリック）と VoiceOver の操作（アクセシビリティのアクション）にも出さなければならない（SHALL）。アカウントの区画を折りたたんでいても、折りたたみの操作を出さない見出しでも、同じように出さなければならない（SHALL）。どの操作でも、見出しの折りたたみが同時に起きてはならない（MUST NOT）。

#### Scenario: ホバーで操作が出る

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しにマウスを載せる
- **THEN** 見出しの右端に Web の通知一覧、すべて既読、すべて Done のボタンがこの順に出る
- **AND** マウスを見出しから外すとボタンは消える

#### Scenario: 止まっているアカウントの見出し

- **GIVEN** `github.com/bob` がスコープ不足で止まっていて、見出しに折りたたみの操作が出ていない
- **WHEN** ユーザーが `bob` の見出しにマウスを載せる
- **THEN** 見出しの右端に Web の通知一覧のボタンが出る

#### Scenario: コンテキストメニューで Web の通知一覧を開く

- **GIVEN** `github.com/alice` がある
- **WHEN** ユーザーが `alice` の見出しを右クリックし、Web の通知一覧を開く項目を選ぶ
- **THEN** 既定のブラウザで `https://github.com/notifications` が開き、`alice` の区画は折りたたまれない

### Requirement: アカウントの見出しの操作のボタンの配置

ボタンを出している間も、見出しの高さとユーザー名の書き出しの位置を変えてはならない（MUST NOT）。ボタンを出している間は、ユーザー名・アクティブの印・ホスト名・参加のみの印・折りたたんだときの件数をボタンに重ねてはならず（MUST NOT）、収まらないときは「ポップオーバーの文字の読みやすさの幅と省略」の順（ホスト名から、次にユーザー名の末尾）でボタンの手前で省略しなければならない（SHALL）。確認の表示は、マウスを見出しから外しても出し続けなければならない（SHALL）。

#### Scenario: 確認の表示のままマウスを外す

- **GIVEN** ユーザーが `alice` の見出しのすべて既読を 1 回押し、`Mark 3 as read?` の表示になっている
- **WHEN** ユーザーがマウスを見出しから外す
- **THEN** `Mark 3 as read?` の表示は出たままで、Web の通知一覧とすべて Done のボタンも出たまま

#### Scenario: 長いユーザー名の見出しにマウスを載せる

- **GIVEN** 39 文字のユーザー名のアカウントがある
- **WHEN** ユーザーがその見出しにマウスを載せる
- **THEN** ホスト名が先に省略され、ユーザー名は収まらない分だけ末尾が省略されて、どちらもボタンに重ならない

### Requirement: アカウントの見出しの操作のコンテキストメニューと VoiceOver

コンテキストメニューと VoiceOver の操作で Web の通知一覧を開くことを選んだときは、すぐに開かなければならない（SHALL）。すべて既読とすべて Done を選んだときは、すぐには行わずに、見出しのボタンを確認の表示にしなければならない（SHALL。ボタンで押したときと同じく、確認の表示のまま 5 秒以内にそのボタンを押したときだけ行う）。VoiceOver の操作で確認の表示にしたときは、確認を待っていることを読み上げで知らせなければならない（SHALL）。押せないときのすべて既読とすべて Done は、選べないようにしなければならない（SHALL）。

#### Scenario: コンテキストメニューですべて Done を選ぶ

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しを右クリックし、すべて Done を選ぶ
- **THEN** リクエストは送られず、見出しのすべて Done のボタンが `Mark 3 as done?` の表示になる
- **AND** 5 秒以内にそのボタンを押すと、`alice` の一覧のスレッドが Done になる

#### Scenario: 未読が無いときのコンテキストメニュー

- **GIVEN** `github.com/alice` の取得ができていて、未読が 0 件
- **WHEN** ユーザーが `alice` の見出しを右クリックする
- **THEN** すべて既読とすべて Done の項目は選べない

### Requirement: アカウントの見出しのボタンの記号

アカウントの見出しのすべて既読とすべて Done のボタンの記号は、同じ操作をするスレッドの行とリポジトリの見出しのボタンと同じ記号にしなければならない（SHALL）。すべて既読は「既読にする」と同じ封筒の記号、すべて Done は「Done にする」と同じチェックの記号にしなければならない（SHALL）。Web の通知一覧のボタンは、四角の枠から外へ出ていく矢印の記号（外部へ開くことを表す慣用の形）にしなければならない（SHALL）。

#### Scenario: 見出しのボタンの記号

- **GIVEN** `github.com/alice` の一覧に `octo/app` のスレッドが 2 件ある
- **WHEN** ユーザーが `alice` の見出しと `octo/app` の見出しに、順にマウスを載せる
- **THEN** `alice` の見出しのすべて既読とすべて Done のボタンは、`octo/app` の見出しの「既読にする」と「Done にする」のボタンと同じ記号で出る
- **AND** Web の通知一覧のボタンは、四角の枠から外へ出ていく矢印の記号で出る

### Requirement: アカウントの見出しのボタンの大きさ

アカウントの見出しのボタン（Web の通知一覧、すべて既読、すべて Done）は、押せる範囲（マウスを載せたときの塗りの範囲）と記号の枠を、リポジトリの見出しの「既読にする」と「Done にする」のボタンと同じ大きさにしなければならない（SHALL）。確認の表示のときは、確認の文の大きさにしてよい（MAY）。ボタンを出しても、アカウントの見出しの高さ（「見出しの押せる範囲の高さ」）を変えてはならない（MUST NOT）。

#### Scenario: 見出しのボタンの大きさを比べる

- **GIVEN** `github.com/alice` の一覧に `octo/app` のスレッドが 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しの「Done にする」と `alice` の見出しのすべて Done のボタンに、順にマウスを載せる
- **THEN** 2 つのボタンの塗りの範囲は同じ大きさで出る
- **AND** `alice` の見出しの高さは 24pt のまま

### Requirement: すべて Done のボタン

トークンが「使える」アカウントの区画の見出しの操作には、すべて既読の右に、そのアカウントの一覧のスレッドをまとめて Done にする操作がなければならない（SHALL）。この操作は、すべて既読を出すときに出し、すべて既読と同じく、取得の状態が「取得できた」で一覧に 1 件以上あるときだけ押せるようにしなければならない（SHALL。失敗して待っている間に、前の一覧のスレッドをまとめて Done にしないため）。ボタンにはツールチップとアクセシビリティのラベルを付けなければならない（SHALL）。ブラウザを開いてはならない（MUST NOT）。

#### Scenario: すべて Done のボタンが出る

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しにマウスを載せる
- **THEN** すべて既読の右にすべて Done のボタンが出て、押せる

#### Scenario: 未読が無いとき

- **GIVEN** `github.com/alice` の取得ができていて、未読が 0 件
- **WHEN** ユーザーが `alice` の見出しにマウスを載せる
- **THEN** `alice` のすべて Done は押せない

#### Scenario: 取得が失敗して待っているとき

- **GIVEN** `github.com/alice` の取得が失敗して待っていて、最後に取得できた 2 件が表示されている
- **WHEN** ユーザーが `alice` の見出しにマウスを載せる
- **THEN** `alice` のすべて既読とすべて Done は押せない

#### Scenario: 止まっているアカウント

- **GIVEN** `github.com/bob` が「スコープ不足」で止まっている
- **WHEN** ユーザーが `bob` の見出しにマウスを載せる
- **THEN** `bob` の見出しに、すべて Done の押せるボタンは出ない

### Requirement: すべて Done のボタンの確認

すべて Done は取り消せず複数のスレッドに効くので、1 回目に押したときはリクエストを送らずに、ボタンを件数を含む確認の表示（`Mark N as done?`。N はそのアカウントの一覧の件数）に変えなければならない（SHALL）。確認の表示のまま 5 秒以内にもう一度押したときだけ、polling「アカウントのすべて Done」に従って Done にしなければならない（SHALL）。5 秒たったとき、ポップオーバーを閉じたとき、ボタンが押せなくなったとき、一覧のスレッドが変わったとき（件数と最新のスレッドが同じでも、スレッドが入れ替わったときを含む）は、リクエストを送らずに元の表示に戻さなければならない（SHALL）。

#### Scenario: 2 回押してすべて Done にする

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しのすべて Done を押す
- **THEN** ボタンは `Mark 3 as done?` の表示に変わり、リクエストは送られない
- **AND** 5 秒以内にもう一度押すと、`alice` の一覧が空になり、スレッドごとに `DELETE /notifications/threads/{id}` が送られる

#### Scenario: 確認せずに時間が過ぎる

- **GIVEN** ユーザーが `alice` のすべて Done を 1 回押し、確認の表示になっている
- **WHEN** 5 秒がたつ
- **THEN** ボタンは元の表示に戻り、リクエストは送られない

#### Scenario: 確認の途中でスレッドが入れ替わる

- **GIVEN** `alice` の一覧にスレッド `1`（12:30）と `2`（12:00）があり、ユーザーがすべて Done を 1 回押して `Mark 2 as done?` の表示になっている
- **WHEN** 5 秒以内の取得で `2` が消え、スレッド `3`（11:00）が一覧に出る
- **THEN** ボタンは元の表示に戻り、次に押しても確認の表示になるだけでリクエストは送られない

### Requirement: アカウントの見出しの確認の表示

1 つのアカウントの見出しで確認の表示にするのは、すべて既読とすべて Done のどちらか 1 つだけにしなければならない（SHALL）。一方が確認の表示のときにもう一方を押したら、先の確認の表示を元に戻し、押した方を確認の表示にしなければならない（SHALL）。確認の表示は押したアカウントの見出しだけに出し、ほかのアカウントの見出しとリポジトリの見出しに影響してはならない（MUST NOT）。

#### Scenario: すべて既読の確認の途中ですべて Done を押す

- **GIVEN** ユーザーが `alice` のすべて既読を 1 回押し、`Mark 3 as read?` の表示になっている
- **WHEN** ユーザーが `alice` のすべて Done を押す
- **THEN** すべて既読のボタンは元の表示に戻り、すべて Done のボタンが `Mark 3 as done?` の表示になる
- **AND** リクエストは送られない

#### Scenario: ほかのアカウントに影響しない

- **GIVEN** `github.com/alice` と `acme.ghe.com/dave` の一覧にそれぞれスレッドがある
- **WHEN** ユーザーが `alice` のすべて Done を 1 回押す
- **THEN** `alice` のすべて Done だけが確認の表示になり、`dave` の見出しのボタンと `alice` のリポジトリの見出しは変わらない

## MODIFIED Requirements

### Requirement: ポップオーバーの文字の読みやすさ

ポップオーバーに出す文字（一覧、取得の状態、操作の失敗、案内の文、件数、ボタンの文）は、11pt より小さくしてはならない（MUST NOT）（13pt・11pt は macOS のテキストスタイルの大きさで、`.body` / `.headline` が 13pt、`.subheadline` が 11pt）。スレッドの件名とアカウントの見出しのユーザー名は 13pt で出さなければならない（SHALL）。アカウントの見出しのユーザー名とリポジトリの見出し（`owner/name`）は見出しとして、太字（semibold 以上）にし、薄い色にせず標準の文字色で出さなければならない（SHALL）。すべて既読、すべて Done、リポジトリの Done の確認の文は、確認の途中であることが分かるよう、システムのアクセントカラーで出さなければならない（SHALL）。

メニューバーのアイコンと件数、設定ウィンドウの文字には、この Requirement は適用しない。

#### Scenario: スレッドの行

- **GIVEN** `github.com/alice` の `octo/app` に、Pull request `#42`、理由 `review_requested` のスレッドがある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 件名は 13pt で標準の文字色で出る
- **AND** `#42`、理由、更新日時の行は 11pt で薄い色で出る
- **AND** `octo/app` の見出しは 11pt の太字で、標準の文字色で出る

#### Scenario: アカウントの見出し

- **GIVEN** `acme.ghe.com/dave`（使える、アクティブ）がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` は 13pt の太字で、標準の文字色で出る
- **AND** アクティブの印と `acme.ghe.com` は 11pt で出る

#### Scenario: すべて既読の確認

- **GIVEN** `github.com/alice` に未読が 3 件ある
- **WHEN** ユーザーがすべて既読のボタンを 1 回押す
- **THEN** 確認の文はシステムのアクセントカラーで、11pt の太字で出る

### Requirement: ポップオーバーの文字の読みやすさの幅と省略

文字を大きくしても、ポップオーバーの幅（380pt）は変えてはならず（MUST NOT）、横にスクロールさせてはならない（MUST NOT）。アカウントの見出しは 1 行に収めなければならない（SHALL）。幅が足りないときは、まずホスト名を省略し、それでも足りなければユーザー名の末尾を省略しなければならない（SHALL）。アクティブの印、折りたたんだときの件数、すべて既読、すべて Done、リポジトリの Done の確認の文は省略してはならない（MUST NOT）。リポジトリの見出しは 1 行に収め、収まらないときは中央を省略しなければならない（SHALL）。ユーザー名・ホスト名・リポジトリ名を省略したときは、その文字にマウスを載せたツールチップで全体を読めなければならない（SHALL）。省略していないときは、同じ文のツールチップを出してはならない（MUST NOT）。スレッドの件名は 2 行まで出し、それより長いときは省略しなければならない（SHALL）。

#### Scenario: 長いホスト名と件名

- **GIVEN** ホスト名が 40 文字以上ある GHES のアカウントに、件名が 200 文字のスレッドがある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** ポップオーバーの幅は 380pt のままで、横にスクロールしない
- **AND** 見出しのホスト名は 1 行に省略して出て、件名は 2 行まで出て省略される
- **AND** ホスト名にマウスを載せると、ツールチップで全体が読める

#### Scenario: 長いユーザー名

- **GIVEN** 39 文字のユーザー名のアクティブなアカウントで、すべて既読のボタンを 1 回押して確認の文が出ている
- **WHEN** ユーザーがポップオーバーを見る
- **THEN** 見出しは 1 行のままで、ホスト名が先に省略され、ユーザー名は収まらない分だけ末尾が省略される
- **AND** ユーザー名にマウスを載せると、ツールチップで全体が読める
- **AND** アクティブの印と確認の文は省略されない

#### Scenario: 長いリポジトリ名

- **GIVEN** 長い `owner/name` のリポジトリの未読がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** リポジトリの見出しは 1 行で、中央が省略される
- **AND** 見出しにマウスを載せると、ツールチップで `owner/name` の全体が読める

#### Scenario: 短い名前

- **GIVEN** `github.com/alice` の `octo/app` に未読がある
- **WHEN** ユーザーが見出しのユーザー名・ホスト名・リポジトリ名にマウスを載せる
- **THEN** 名前は省略されずに出ている
- **AND** 同じ文のツールチップは出ない

### Requirement: ポップオーバーの押せる要素のホバーの反応

ポップオーバーの次の要素は、マウスを載せている間、押せる範囲に薄い塗りを出して、押せることと押したときに反応する範囲が分かるようにしなければならない（SHALL）。押している間は、マウスを載せているときより濃い塗りにしなければならない（SHALL）。

- アイコンだけのボタン: 見出しの歯車と再読み込み、スレッドの行の「既読にする」と「Done にする」、リポジトリの見出しの「既読にする」と「Done にする」（確認の表示のときも含む）、アカウントの見出しの Web の通知一覧のボタン、すべて既読のボタン、すべて Done のボタン（すべて既読とすべて Done は確認の表示のときも含む）、コマンドの行のコピーのボタン
- スレッドの行（クリックでスレッドを開く範囲）
- アカウントの見出しとリポジトリの見出しの、折りたたみの操作の範囲

#### Scenario: 見出しのアイコンのボタンにマウスを載せる

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しのすべて既読のボタンにマウスを載せ、続けて Web の通知一覧のボタンにマウスを載せる
- **THEN** マウスを載せているボタンのアイコンの後ろにだけ、角丸の薄い塗りが出る

### Requirement: ポップオーバーの押せる要素のホバーの塗り

塗りは、システムの文字色を薄く重ねた角丸の塗りにし、独自の色を使ってはならない（MUST NOT）。これは「ポップオーバーの文字の読みやすさの色の指定と背景」が許すボタンの囲みの塗りであり、文字の色を変えてはならない（MUST NOT。すべて既読、すべて Done、リポジトリの Done の確認の文はアクセントカラーのまま）。マウスを外したら塗りを消さなければならない（SHALL）。押せないとき（再読み込み中の再読み込みのボタン、押せないすべて既読とすべて Done のボタン）と、折りたたみの操作を出さない見出しには、塗りを出してはならない（MUST NOT）。塗りを出しても、行と見出しの高さ、アイコンと文字の位置、件名の折り返しは変えてはならない（MUST NOT）。

システム標準の押しボタン（Quit、Open Settings…、Open cli.github.com など）は、macOS の標準の見た目のままにし、独自の塗りを付けてはならない（MUST NOT）。

#### Scenario: すべて既読の確認の表示

- **GIVEN** ユーザーが `alice` の「すべて既読」を 1 回押し、`Mark 3 as read?` の表示になっている
- **WHEN** ユーザーがそのボタンにマウスを載せる
- **THEN** 確認の文の後ろに角丸の薄い塗りが出て、文はアクセントカラーのまま

#### Scenario: 押せないボタン

- **GIVEN** `github.com/alice` の取得ができていて、未読が 0 件
- **WHEN** ユーザーが `alice` の見出しのすべて既読のボタンにマウスを載せる
- **THEN** 塗りは出ない

#### Scenario: 折りたたみの操作を出さない見出し

- **GIVEN** `ghe.example.com/dave` が「トークンを取れない」
- **WHEN** ユーザーが `dave` の見出しにマウスを載せる
- **THEN** 見出しに塗りは出ない

#### Scenario: 標準の押しボタン

- **GIVEN** ポップオーバーが開いている
- **WHEN** ユーザーが Quit ボタンにマウスを載せる
- **THEN** Quit ボタンは macOS の標準の押しボタンの見た目のままで、独自の塗りは出ない

### Requirement: ポップオーバーの押せる要素のホバーの範囲

スレッドの行では、行の塗りはマウスを載せた行の全体に出し、「既読にする」と「Done にする」のボタンを出している間も、ボタンの下を含めて行の全体に出し続けなければならない（SHALL）。ボタンにマウスを載せたときは、行の塗りの上にボタンの塗りを重ねて出さなければならない（SHALL）。リポジトリとアカウントの見出しの折りたたみの操作の範囲は、見出しの行の幅いっぱいにしなければならない（SHALL）。どちらの見出しでも、操作のボタンを出している間も、ボタンの下を含めて見出しの行の幅いっぱいに塗りを出し続け、ボタンにマウスを載せたときは見出しの塗りの上にボタンの塗りを重ねて出さなければならない（SHALL。スレッドの行と同じ）。

#### Scenario: スレッドの行にマウスを載せる

- **GIVEN** `github.com/alice` の一覧にスレッド `123` がある
- **WHEN** ユーザーが `123` の行にマウスを載せる
- **THEN** `123` の行の全体に薄い塗りが出て、右端に「既読にする」と「Done にする」のボタンが出る
- **AND** 件名の折り返しと行の高さは、マウスを載せる前と変わらない
- **AND** マウスを行から外すと、塗りとボタンは消える

#### Scenario: 行の操作のボタンにマウスを載せる

- **GIVEN** `123` の行にマウスを載せている
- **WHEN** ユーザーがマウスを「Done にする」のボタンの上へ動かす
- **THEN** 行の塗りは出たままで、「Done にする」のアイコンの後ろに角丸の塗りが重なって出る
- **AND** 「既読にする」のアイコンの後ろには塗りが出ない

#### Scenario: リポジトリの見出しにマウスを載せる

- **GIVEN** `github.com/alice` に `octo/app` の通知が 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しの、リポジトリ名より右の空いたところにマウスを載せる
- **THEN** 見出しの行の幅いっぱいに薄い塗りが出る
- **AND** そこを押すと `octo/app` が折りたたまれる

#### Scenario: アカウントの見出しにマウスを載せる

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しの、ホスト名より右の空いたところにマウスを載せる
- **THEN** 見出しの行の幅いっぱいに薄い塗りが出て、右端に Web の通知一覧、すべて既読、すべて Done のボタンが出る
- **AND** ボタンには塗りが出ない
- **AND** 空いたところを押すと `alice` の区画が折りたたまれ、すべて既読とすべて Done のボタンは確認の表示にならない

#### Scenario: リポジトリの見出しの操作のボタンにマウスを載せる

- **GIVEN** `github.com/alice` に `octo/app` の通知が 2 件あり、`octo/app` の見出しにマウスを載せている
- **WHEN** ユーザーがマウスを見出しの「Done にする」のボタンの上へ動かす
- **THEN** 見出しの行の幅いっぱいの塗りは出たままで、「Done にする」のアイコンの後ろに角丸の塗りが重なって出る
- **AND** 見出しの高さとリポジトリ名の書き出しの位置は、マウスを載せる前と変わらない

### Requirement: 見出しの押せる範囲の高さ

ポップオーバーの一覧のアカウントの見出しとリポジトリの見出しでは、折りたたみの操作の押せる範囲（マウスを載せたときの塗りの範囲）の高さを、既定の文字の大きさで 24pt にしなければならない（SHALL）。見出しの中身（山形、アイコン、文字、件数など）がそれより高いときは、中身の高さに合わせ、中身を縮めたり切ったりしてはならない（MUST NOT）。押せる範囲は見出しの上下で中身の外へ広げ、中身は押せる範囲の縦の中央に置かなければならない（SHALL）。

折りたたみの操作を出さない見出し（「一覧の折りたたみの畳める条件」で畳めないとき）も、同じ高さにしなければならない（SHALL）。畳めるかどうかが変わっても、見出しの高さと、見出しの下の表示の位置を変えてはならない（MUST NOT）。

アカウントの見出しのボタンの大きさは「アカウントの見出しのボタンの大きさ」に従い、この決まりで変えてはならない（MUST NOT）。スレッドの行の大きさも、この決まりで変えてはならない（MUST NOT）。

#### Scenario: リポジトリの見出しの上の端を押す

- **GIVEN** `github.com/alice` に `octo/app` の通知が 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しの、リポジトリ名の文字より 3pt 上を押す
- **THEN** `octo/app` が折りたたまれる

#### Scenario: アカウントの見出しにマウスを載せる

- **GIVEN** `github.com/alice` の取得ができていて、未読が 3 件ある
- **WHEN** ユーザーが `alice` の見出しにマウスを載せる
- **THEN** 塗りの高さは 24pt で、山形・トークンの状態・ユーザー名は塗りの縦の中央に出る

#### Scenario: 畳めるようになっても見出しの高さは変わらない

- **GIVEN** `github.com/alice` が最初の取得中で、見出しに折りたたみの操作が出ていない
- **WHEN** 取得ができて、見出しに折りたたみの操作が出る
- **THEN** 見出しの高さと、その下の取得の状態の表示の位置は変わらない

### Requirement: アカウント一覧の表示

全体の状態が「アカウントあり」のとき、ポップオーバーは「無効」以外のアカウントごとの区画を、accounts の並び順で表示しなければならない（SHALL）。「無効」のアカウントの区画は出してはならない（MUST NOT）。すべてのアカウントが「無効」のときは、区画の代わりに、すべてのアカウントが無効であることと、設定ウィンドウを開くボタンを表示しなければならない（SHALL）。区画の見出しにはユーザー名、ホスト名、トークンの状態（取得中 / 使える / トークンを取れない）を出し、ホスト種別（GitHub.com / GHE Cloud / Enterprise Server）は出してはならない（MUST NOT。ホスト名で分かり、github.com では同じ名前が続くため）。gh のアクティブなアカウントの見出しには、そうと分かる印を付けなければならない（SHALL）。「参加しているスレッドだけにする」がオンのアカウントの見出しには、そうと分かる印を付けなければならない（SHALL）。トークンの値やその一部、API の URL を表示してはならない（MUST NOT）。

#### Scenario: 2 つのホストのアカウントを表示する

- **GIVEN** `github.com/alice`（使える、アクティブ）と `acme.ghe.com/dave`（使える）がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画の見出しに `github.com` とアクティブの印が、`dave` の区画の見出しに `acme.ghe.com` が表示される
- **AND** どちらの見出しにも、ホスト種別（GitHub.com、GHE Cloud）は表示されない
- **AND** どちらも「使える」状態として表示される

#### Scenario: トークンを取れないアカウント

- **GIVEN** `ghe.example.com/dave` が「トークンを取れない」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` の区画に警告と、実行すべきコマンド `gh auth login --hostname ghe.example.com` が表示される
- **AND** コマンドをクリップボードにコピーするボタンがある

#### Scenario: 無効のアカウントは出さない

- **GIVEN** `github.com/alice`（使える）と `github.com/bob`（無効）がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画だけが表示され、`bob` の区画は無い

#### Scenario: すべてのアカウントが無効

- **GIVEN** `github.com/alice` と `github.com/bob` のどちらも「無効」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** すべてのアカウントが無効であることと、設定ウィンドウを開くボタンが表示される

#### Scenario: 参加しているスレッドだけにしたアカウント

- **GIVEN** `acme.ghe.com/dave` の「参加しているスレッドだけにする」がオン
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` の区画の見出しに、参加しているスレッドだけを表示していることを示す印が出る

### Requirement: アカウント一覧の表示の通知の一覧

トークンが「使える」アカウントの区画には、見出しに通知の取得の状態を出し、その下に未読の通知をリポジトリ（`owner/name`）ごとにまとめて表示しなければならない（SHALL）。リポジトリは含まれるスレッドの最新の更新日時が新しい順に、スレッドは更新日時が新しい順に並べなければならない（SHALL）。スレッドの行には、種類（Pull request / Issue / Commit / Release / Discussion など）を表すアイコン、件名、理由（`reason`）、更新日時を出さなければならない（SHALL）。未読の通知が 0 件のときは、そうと分かる表示を出さなければならない（SHALL）。一覧がポップオーバーに収まらないときは、見出しの「Mewbell」と Quit ボタンを残したまま一覧だけをスクロールできなければならない（SHALL）。

#### Scenario: 2 つのアカウントの通知を表示する

- **GIVEN** `github.com/alice`（使える、アクティブ）に `octo/app` の通知が 2 件と `octo/lib` の通知が 1 件あり、`acme.ghe.com/dave`（使える）に `acme/web` の通知が 1 件ある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画（`github.com`、アクティブの印付き）の下に `octo/app` と `octo/lib` の見出しと、それぞれのスレッドが表示される
- **AND** `dave` の区画（`acme.ghe.com`）の下に `acme/web` の見出しとスレッドが表示される

#### Scenario: 未読が無い

- **GIVEN** `github.com/alice` の取得ができていて、未読の通知が 0 件
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に、未読の通知が無いことを示す表示が出る

### Requirement: ポップオーバーの文字の読みやすさの文字色

薄い色（システムの副次的な文字色）は、次の補足の情報にだけ使わなければならない（SHALL）: スレッドの行の番号・理由・更新日時、ホスト名、トークンの状態が取得中であることの表示（「Checking gh…」）、gh を探している途中であることの表示（案内画面の「Checking gh…」）、通知の取得中・取得できた時刻の表示（「Loading notifications…」「Updated …」）、未読が無いことの表示、折りたたんだときの件数。この一覧に無い文は、すべて標準の文字色で出さなければならない（SHALL）。例えば、トークンを取れないときやスコープ不足・認証エラーの案内、取得に失敗して待っていることの文（「Rate limited. Retrying at …」など）、操作の失敗、一覧を打ち切ったことの知らせがそうである。

メニューバーのアイコンと件数、設定ウィンドウの文字には、この Requirement は適用しない。

#### Scenario: 取得の状態と操作の失敗

- **GIVEN** `github.com/alice` の取得ができていて、直前の既読の操作が失敗している
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 「Updated」の行と操作の失敗の文は 11pt で出る
- **AND** 操作の失敗の文は標準の文字色で出る

#### Scenario: トークンを取れないときの案内

- **GIVEN** `ghe.example.com/dave` が「トークンを取れない」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 案内の文は 11pt で標準の文字色で出る
- **AND** 案内の文とコマンドの行は、ほかの区画の案内と同じ字下げで出る

### Requirement: Web の通知一覧を開く

一覧に出ているアカウントの区画（無効のアカウントの区画は出さない）の見出しには、そのアカウントのホストの Web の通知一覧を既定のブラウザで開くボタンがなければならない（SHALL）。このボタンは「アカウントの見出しの操作」に従って出し、トークンの状態（取得中・使える・取得できない）と取得の状態（取得中・取得できた・失敗して待っている・スコープ不足・認証エラー）にかかわらず、押せるようにしなければならない（SHALL）。ボタンを押しても、スレッドの既読・Done・すべて既読のリクエストを送ってはならず（MUST NOT）、一覧のスレッドを外してはならない（MUST NOT）。ボタンには、開く先のホストを含むツールチップとアクセシビリティのラベル（`Open notifications on <host>` など）を付けなければならない（SHALL）。

#### Scenario: github.com のアカウントの通知一覧を開く

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しにマウスを載せ、Web の通知一覧のボタンを押す
- **THEN** 既定のブラウザで `https://github.com/notifications` が開く
- **AND** `alice` の一覧の 3 件は残り、既読化のリクエストは送られない

#### Scenario: 取得が止まっているアカウント

- **GIVEN** `github.com/bob` がスコープ不足で止まっていて、`ghe.example.com/frank` はトークンを取得できない
- **WHEN** ユーザーが `bob` と `frank` の見出しに、順にマウスを載せる
- **THEN** `bob` と `frank` の見出しにも Web の通知一覧のボタンが出て、押すとそれぞれ `https://github.com/notifications` と `https://ghe.example.com/notifications` が開く

#### Scenario: 無効のアカウント

- **GIVEN** `github.com/carol` が無効
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `carol` の区画は出ず、`carol` の Web の通知一覧のボタンも出ない
