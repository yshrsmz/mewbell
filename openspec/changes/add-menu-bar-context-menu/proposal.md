# Proposal

## Why

アプリの終了はポップオーバーの下端の Quit ボタンでしかできず、通知の一覧の下に毎回ボタンの行が場所を取っている。メニューバー常駐のアプリでは、アイコンの右クリック（Control+クリック）で設定・終了などのアプリ全体の操作を出すのが macOS の慣習で、今の Mewbell では右クリックしても左クリックと同じくポップオーバーが開くだけになっている。右クリックのメニューにアプリ全体の操作をまとめ、ポップオーバーは通知の一覧に集中させる。

マイルストーン: M4「設定と操作」の追補。

## What Changes

- メニューバーの猫アイコンを右クリック、または Control+クリックすると、ポップオーバーを開かずに、アイコンの下にメニューを出す。左クリックの動き（ポップオーバーを開く）は変えない
- メニューの項目は次の順にする: About Mewbell、区切り、Settings…（⌘,）、Mewbell の Releases ページを開く項目、区切り、Quit Mewbell（⌘Q）
  - About Mewbell: macOS 標準の About パネルを出し、アプリ名・バージョン・著作権表示を見せる。自動更新が無いので、不具合の報告のときに版を確かめる手段にする
  - Settings…: ポップオーバーの歯車と同じく設定ウィンドウを開き、前面に出す
  - Releases ページ: 固定の URL `https://github.com/yshrsmz/mewbell/releases` を既定のブラウザで開く。Sparkle などの自動更新は入れない方針なので、新しい版を探す入口にする
  - Quit Mewbell: アプリを終了する（終了前にポーリングを止めてトークンを捨てる今の処理を通す）
- **BREAKING（操作）**: ポップオーバーの下端の Quit ボタンと、その上の区切りを消す。ポップオーバーを開いている間の ⌘Q での終了もなくなる（メニューバー常駐のアプリにはメインメニューが無いため）。メニューの Quit の ⌘Q は、メニューを開いている間だけ効く
- ポップオーバーを開いたまま右クリックしたときは、ポップオーバーを閉じてメニューを出す

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `ui`: 「ポップオーバーの表示」から Quit ボタンを外す。「アプリの終了」を右クリックのメニューの Quit に改める。右クリックのメニューの要件を足す。「案内画面」と「ポップオーバーの押せる要素のホバーの塗り」の Quit を前提にした文と Scenario を直す
- `settings`: 右クリックのメニューの Settings… から設定ウィンドウを開く要件を足す（開き方は既存の「設定ウィンドウを開く」と同じ）

## Impact

- コード: `Mewbell/App/`（右クリックの検出とメニュー、`AppDelegate` での組み立て）、`Mewbell/App/MenuBarContentView.swift`（Quit ボタンを消す）、`Mewbell/UI/OpenSettingsButton.swift` 周辺（設定ウィンドウを開く処理をメニューからも使う）、テスト
- `docs/architecture.md`: A16 の標準の押しボタンの例に Quit が挙がっているので、例を差し替える
- トークン: 直接は触れない。Quit は既存の `applicationShouldTerminate` を通り、ポーリングを止めてメモリ上のトークンを捨てる今の処理をそのまま使う。永続化はしない
- ネットワーク: 触れない
- URL を開く処理: 触れる。コードに書いた固定の `https` の URL（Releases ページ）だけを開き、API が返す値やユーザーの入力から URL を組み立てない
- gh サブプロセス: 触れない
- 永続化: しない
