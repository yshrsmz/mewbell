# Proposal

## Why

macOS のスクロールバーが常に出る設定（「スクロールバーを表示」が「常に」のとき、または「マウスまたはトラックパッドに応じて自動的に」でマウスをつないでいるとき。以下 legacy スタイル）では、スクロールバーが中身に重ならずに一覧の幅を使う。そのため、一覧がポップオーバーに収まるかどうかでスクロールバーが出たり消えたりするたびに、一覧の中身の幅がスクロールバーの幅だけ変わる。開閉のアニメーションの間にスクロールバーを隠すときも同じことが起きる。スレッドの行の右端の既読・Done のボタン、リポジトリの見出しのボタン、アカウントの見出しの Web の通知一覧とすべて既読のボタンは中身の右端に揃えているので、幅が変わると横にずれる。Done を続けて押して一覧が短くなり、収まった瞬間にボタンがカーソルの下から外れて、続けて押せなくなる。

マイルストーン: M4（設定と操作）で足した操作の不具合の修正。新しい操作は足さない。SETUP.md のマイルストーンの表には行を足さない。

## What Changes

- legacy スタイルでは、スクロールバーが出ていないとき（一覧がポップオーバーに収まっているとき、開閉のアニメーションでスクロールバーを隠しているとき）にも、一覧の中身の右にスクロールバーと同じ幅の空きを残す。スクロールバーが出ているかどうかで、一覧の中身の幅が変わらないようにする
- スクロールバーが中身に重なる設定（overlay スタイル。トラックパッドだけの既定）では、今と同じく空きを残さない
- 一覧を開いたままシステム設定でスクロールバーの表示を切り替えたときも、切り替えた後の表示に合わせる
- ポップオーバーの幅（380pt）、スクロールバーを出す条件、開閉のアニメーションの間にスクロールバーを隠すことは変えない

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `ui`: 一覧のスクロールバーが出たり消えたりしても、一覧の中身の幅（と、右端に揃えたボタンの位置）を変えないことを足す（新しい Requirement）。既存の「アカウント一覧の表示」の「一覧だけをスクロールできる」と、「ポップオーバーの文字の読みやすさ」の「幅を 380pt から変えない・横にスクロールさせない」は変えない

## Impact

- コード: `Mewbell/UI/AccountSectionView.swift`（`NotificationListView` の `ScrollView` と、`HidesScrollIndicatorsWhileAnimating`）。スクロールバーの空きを決める部品を `UI/` に足す
- テスト: 空きの幅を決める判断の単体テストを足す
- トークン: 触れない
- gh サブプロセス: 触れない
- ネットワーク: 触れない
- URL を開く処理: 触れない
- 永続化: しない。スクロールバーの表示のしかたは AppKit（`NSScroller.preferredScrollerStyle`）から読み、はみ出しているかどうかは View の中にだけ持つ
