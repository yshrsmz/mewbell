# settings Specification

## Purpose
Mewbell の設定ウィンドウの構成と開き方、設定項目とその既定値、設定の保存先と保存してはならないもの、変更をすぐ反映すること、ログイン時起動の登録を定める。各設定が通知の取得・アカウント・gh の扱いをどう変えるかは、それぞれの capability の spec で定める。

## Requirements

### Requirement: 設定ウィンドウを開く

Mewbell は、ポップオーバーの見出しの設定ボタン（歯車）を押したとき、およびポップオーバーにキーボードフォーカスがある状態で ⌘, を押したときに、設定ウィンドウを開かなければならない（SHALL）。設定ウィンドウを開くときはポップオーバーを閉じ、設定ウィンドウをほかのアプリのウィンドウより前面に出して、キーボードフォーカスを与えなければならない（SHALL）。設定ウィンドウがすでに開いているときは、2 つ目を開かずに今のウィンドウを前面に出さなければならない（MUST）。設定ウィンドウを開いている間も、Dock に Mewbell のアイコンを出してはならない（MUST NOT）。設定ウィンドウには General、Accounts、gh、Diagnostics の 4 つのタブがこの順でなければならない（SHALL）。Diagnostics タブの中身は diagnostics の spec で定める。

#### Scenario: 歯車ボタンで開く

- **GIVEN** ほかのアプリが前面にあり、Mewbell のポップオーバーを開いている
- **WHEN** ユーザーがポップオーバーの見出しの歯車ボタンを押す
- **THEN** ポップオーバーが閉じ、設定ウィンドウがほかのアプリのウィンドウより前面に開く
- **AND** Dock に Mewbell のアイコンは出ない

#### Scenario: すでに開いている

- **GIVEN** 設定ウィンドウが開いていて、ほかのアプリのウィンドウの後ろに隠れている
- **WHEN** ユーザーがポップオーバーを開いて ⌘, を押す
- **THEN** 設定ウィンドウは 1 つのまま、前面に出る

#### Scenario: 4 つのタブ

- **GIVEN** 設定ウィンドウを開いている
- **WHEN** ユーザーがタブの並びを見る
- **THEN** General、Accounts、gh、Diagnostics の 4 つのタブがこの順に並んでいる

### Requirement: 設定項目と既定値

Mewbell の設定は次の項目だけでなければならず（MUST）、値が保存されていない項目は既定値として扱わなければならない（MUST）。

| 範囲 | 項目 | 既定値 |
|---|---|---|
| 全体 | macOS の通知に音を付ける | オン |
| 全体 | gh の実行ファイルのパスの上書き | なし（gh-cli「gh 実行ファイルの検出」の順に探す） |
| 全体 | gh の設定ディレクトリの上書き | なし（gh-cli「hosts.yml の場所と読み取り」の順に決める） |
| アカウントごと | 有効 | オン |
| アカウントごと | 参加しているスレッドだけにする（`participating=true`） | オフ |
| アカウントごと | macOS の通知を出す | オン |

ログイン時に起動するかどうかは、Mewbell の設定として保存せず、macOS のログイン項目の登録の状態をそのまま使わなければならない（MUST）。

#### Scenario: 初めて起動したとき

- **GIVEN** Mewbell の設定を一度も変えたことがない
- **WHEN** ユーザーが `github.com/alice` で Mewbell を使う
- **THEN** `alice` は有効で、`participating=false` で取得され、macOS の通知は音付きで出る

### Requirement: アカウントごとの設定の識別と保持

アカウントごとの設定は `<host>/<user>`（ホスト名は小文字）で識別しなければならない（MUST）。gh からログアウトして一覧から消えたアカウントの設定は消さずに残し、同じアカウントでログインし直したときに同じ設定に戻らなければならない（SHALL）。

#### Scenario: ログインし直すと設定が戻る

- **GIVEN** `github.com/bob` を無効にした後、ユーザーが `gh auth logout --user bob` を実行し、Mewbell がアカウントを読み直した
- **WHEN** ユーザーが `gh auth login` で `bob` にログインし直し、Mewbell がアカウントを読み直す
- **THEN** `bob` は無効のまま一覧に戻る

### Requirement: 設定の保存

Mewbell は設定を、アプリの UserDefaults（`com.codingfeline.mewbell`）にだけ保存しなければならない（MUST）。保存してよいのは、真偽値、アカウントの識別子（`<host>/<user>`）、ファイルやディレクトリのパスだけでなければならない（MUST）。トークンやその一部、API の URL、gh の標準出力・標準エラー出力、API のレスポンスを保存してはならない（MUST NOT）。保存した値が想定した型でない、または読めないときは、その項目を既定値として扱い、アプリの起動を止めてはならない（MUST NOT）。設定はアプリを終了しても残り、次に起動したときに同じ値で始まらなければならない（SHALL）。

#### Scenario: 再起動しても設定が残る

- **GIVEN** ユーザーが `github.com/alice` を「参加しているスレッドだけにする」にした
- **WHEN** Mewbell を終了して起動し直す
- **THEN** `alice` の通知は `participating=true` で取得される

#### Scenario: 設定にトークンは無い

- **GIVEN** `github.com/alice` と `acme.ghe.com/dave` が「使える」で、ユーザーがすべての設定項目を一度ずつ変えた
- **WHEN** `defaults read com.codingfeline.mewbell` で設定を読む
- **THEN** トークンの値、`https://api.` で始まる URL、gh の出力はどこにも無い

#### Scenario: 壊れた値

- **GIVEN** UserDefaults の通知の音の項目に、真偽値ではなく文字列が入っている
- **WHEN** Mewbell を起動する
- **THEN** 通知の音はオン（既定値）として扱われ、Mewbell はいつもどおり起動する

### Requirement: 変更をすぐ反映する

Mewbell は、設定ウィンドウでの変更を、適用ボタンや再起動を求めずにすぐ反映しなければならない（SHALL）。切り替え（トグル）は切り替えた時点で、パスの上書きは確定した時点（入力欄で Return を押したとき、ファイルの選択のダイアログで選んだとき、上書きを消すボタンを押したとき）で反映しなければならない（SHALL）。パスの入力の途中の値で gh を探したり `hosts.yml` を読んだりしてはならない（MUST NOT）。

#### Scenario: アカウントを無効にするとすぐ消える

- **GIVEN** ポップオーバーの一覧に `github.com/bob` の通知が 3 件あり、設定ウィンドウを開いている
- **WHEN** ユーザーが Accounts タブで `bob` の「有効」を切る
- **THEN** `bob` の区画と通知がポップオーバーの一覧と未読バッジからすぐに外れる

#### Scenario: パスの入力の途中では探さない

- **GIVEN** gh タブで gh のパスの入力欄に文字を打っている
- **WHEN** ユーザーが `/opt/home` まで打った
- **THEN** Mewbell は gh を探し直さない
- **AND** ユーザーが `/opt/homebrew/bin/gh` まで打って Return を押すと、そのパスで gh を探し直す

### Requirement: ログイン時に起動する

設定ウィンドウの General タブには「ログイン時に起動する」の切り替えがなければならない（SHALL）。オンにしたら Mewbell を macOS のログイン項目（メインアプリ）として登録し、オフにしたら登録を外さなければならない（SHALL）。切り替えの表示は、設定ウィンドウを開いたときと切り替えた後に macOS の登録の状態を読み直して合わせなければならない（SHALL。システム設定で外されたときにずれないように）。登録にユーザーの承認が要るときは、そうと分かる表示と、システム設定のログイン項目の画面を開くボタンを出さなければならない（SHALL）。登録や解除に失敗したときは、切り替えを macOS の登録の状態に戻し、失敗したことを短く表示しなければならない（SHALL）。そのとき、システムのエラーの文をそのまま出してはならない（MUST NOT）。

#### Scenario: ログイン時に起動する

- **GIVEN** Mewbell はログイン項目に登録されていない
- **WHEN** ユーザーが「ログイン時に起動する」をオンにし、ログアウトしてログインし直す
- **THEN** Mewbell が起動して、メニューバーに猫のアイコンが出る

#### Scenario: システム設定で外された

- **GIVEN** 「ログイン時に起動する」をオンにした後、ユーザーがシステム設定のログイン項目で Mewbell を外した
- **WHEN** ユーザーが設定ウィンドウを開く
- **THEN** 「ログイン時に起動する」はオフになっている

#### Scenario: 承認が要る

- **GIVEN** 「ログイン時に起動する」をオンにしたが、macOS がユーザーの承認を待っている
- **WHEN** ユーザーが General タブを見る
- **THEN** 承認が要ることと、システム設定のログイン項目を開くボタンが出る

### Requirement: Accounts タブ

設定ウィンドウの Accounts タブは、全体の状態が「アカウントあり」のとき、gh にログイン済みのすべてのアカウント（無効にしたものを含む）を accounts の並び順で並べ、それぞれにユーザー名、ホスト名、ホスト種別と、「有効」「参加しているスレッドだけにする」「macOS の通知を出す」の 3 つの切り替えを出さなければならない（SHALL）。無効のアカウントでは、残りの 2 つの切り替えを押せないようにし、値は保ったままにしなければならない（SHALL）。「参加しているスレッドだけにする」には、オンにすると、一覧に出ていない未読も「すべて既読」で既読になることを説明に書かなければならない（SHALL）。全体の状態が「アカウントあり」以外のときは、アカウントの代わりに、gh にログイン済みのアカウントが無いか読めないことと、ポップオーバーの案内を見るよう促す文を出さなければならない（SHALL）。トークンの値やその一部、API の URL を表示してはならない（MUST NOT）。

#### Scenario: アカウントを並べる

- **GIVEN** `github.com/alice`（アクティブ、有効）、`github.com/bob`（無効）、`acme.ghe.com/dave`（有効）がある
- **WHEN** ユーザーが Accounts タブを開く
- **THEN** `alice`、`bob`、`dave` の順に並び、`bob` の「参加しているスレッドだけにする」と「macOS の通知を出す」は押せない

#### Scenario: アカウントが無い

- **GIVEN** 全体の状態が「未ログイン」
- **WHEN** ユーザーが Accounts タブを開く
- **THEN** アカウントが無いことと、ポップオーバーの案内を見るよう促す文が出る

### Requirement: gh タブ

設定ウィンドウの gh タブには、gh の実行ファイルのパスの上書きと、gh の設定ディレクトリの上書きの 2 つの入力がなければならない（SHALL）。それぞれに、パスを打てる入力欄、ファイル（またはディレクトリ）を選ぶダイアログを開くボタン、上書きを消して既定の探し方に戻すボタンを付けなければならない（SHALL）。上書きが無いときは、入力欄に既定の探し方を示す控えの文を出さなければならない（SHALL）。上書きしたパスが gh-cli の検証を通らないときは、その入力の下に使えないことを示す表示を出さなければならない（SHALL）。gh や `hosts.yml` の中身、gh の出力を表示してはならない（MUST NOT）。

#### Scenario: 使えないパスを上書きする

- **GIVEN** `/tmp/gh` が誰でも書き込めるファイル
- **WHEN** ユーザーが gh のパスに `/tmp/gh` を入れて Return を押す
- **THEN** 入力の下に、そのパスの gh は使えないことが表示される

#### Scenario: 上書きを消す

- **GIVEN** gh のパスを `/Users/me/bin/gh` で上書きしている
- **WHEN** ユーザーが上書きを消すボタンを押す
- **THEN** 入力欄は空になって既定の探し方の控えの文が出て、Mewbell は `/opt/homebrew/bin/gh` から探し直す

### Requirement: 設定ウィンドウからの終了

設定ウィンドウの General タブの最後には、Quit Mewbell のボタンがなければならない（SHALL）。押すと、右クリックのメニューの Quit Mewbell（ui「アプリの終了」）と同じく、アプリは終了しなければならない（MUST）。メニューバーのアイコンの右クリックのメニューを出せないときにも、ポップオーバーの歯車から設定ウィンドウを開いて終了できるようにするためである。

#### Scenario: General タブから終了する

- **GIVEN** 設定ウィンドウの General タブを開いている
- **WHEN** ユーザーが Quit Mewbell のボタンを押す
- **THEN** Mewbell のプロセスが終了する
- **AND** メニューバーから猫アイコンが消える

### Requirement: 右クリックのメニューから設定ウィンドウを開く

Mewbell は、メニューバーの猫アイコンの右クリックのメニュー（ui「メニューバーのアイコンの右クリックのメニュー」）で Settings… を選んだとき、およびそのメニューを開いている間に ⌘, を押したときに、設定ウィンドウを開かなければならない（SHALL）。開き方は「設定ウィンドウを開く」と同じでなければならない（SHALL。ほかのアプリのウィンドウより前面に出してキーボードフォーカスを与え、すでに開いていれば 2 つ目を開かずに前面に出し、Dock に Mewbell のアイコンを出さない）。

#### Scenario: メニューの Settings… で開く

- **GIVEN** ほかのアプリが前面にあり、設定ウィンドウは開いていない
- **WHEN** ユーザーが猫アイコンを右クリックして Settings… を選ぶ
- **THEN** 設定ウィンドウがほかのアプリのウィンドウより前面に開く
- **AND** Dock に Mewbell のアイコンは出ない

#### Scenario: すでに開いている設定ウィンドウを前に出す

- **GIVEN** 設定ウィンドウが開いていて、ほかのアプリのウィンドウの後ろに隠れている
- **WHEN** ユーザーが猫アイコンを右クリックして Settings… を選ぶ
- **THEN** 設定ウィンドウは 1 つのまま、前面に出る
