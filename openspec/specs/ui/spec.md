# ui Specification

## Purpose
Mewbell をメニューバー常駐アプリとして見せるための外形を定める。メニューバーのアイコン、クリックで開くポップオーバー、Dock に出ないこと、アプリの終了方法、二重起動の防止、アカウントと通知の一覧、案内画面を対象とする。設定ウィンドウの中身は settings の spec で定める。

## Requirements

### Requirement: メニューバーへの常駐

アプリは起動すると macOS のメニューバーに猫のアイコンを 1 つ表示し、終了するまで表示し続けなければならない（MUST）。アプリは Dock にアイコンを出してはならず（MUST NOT）、起動時にメインウィンドウを開いてはならない（MUST NOT）。

#### Scenario: 起動するとメニューバーに猫アイコンが出る

- **GIVEN** Mewbell が起動していない
- **WHEN** ユーザーが Mewbell を起動する
- **THEN** メニューバーに猫のアイコンが 1 つ表示される
- **AND** Dock に Mewbell のアイコンは表示されない
- **AND** ウィンドウは開かない

#### Scenario: ダークモードでもアイコンが見える

- **GIVEN** Mewbell が起動している
- **WHEN** システムの外観をライトとダークで切り替える
- **THEN** メニューバーの猫アイコンはどちらの外観でもメニューバーの他のアイコンと同様に判別できる

### Requirement: ポップオーバーの表示

メニューバーの猫アイコンをクリックすると、アプリはアイコンの下にポップオーバーを開き、アプリ名「Mewbell」、設定ウィンドウを開く歯車のボタン（settings「設定ウィンドウを開く」）、Quit ボタンを表示しなければならない（SHALL）。歯車のボタンにはツールチップとアクセシビリティのラベルを付けなければならない（SHALL）。歯車のボタンは、全体の状態にかかわらず（案内画面を出しているときも）表示しなければならない（SHALL）。ポップオーバーの外をクリックすると閉じなければならない（SHALL）。

#### Scenario: アイコンをクリックするとポップオーバーが開く

- **GIVEN** Mewbell が起動していて、ポップオーバーは閉じている
- **WHEN** ユーザーがメニューバーの猫アイコンをクリックする
- **THEN** アイコンの下にポップオーバーが開く
- **AND** ポップオーバーに「Mewbell」と表示される
- **AND** ポップオーバーに歯車のボタンと Quit ボタンが表示される

#### Scenario: 外側をクリックすると閉じる

- **GIVEN** ポップオーバーが開いている
- **WHEN** ユーザーがポップオーバーの外側をクリックする
- **THEN** ポップオーバーが閉じる
- **AND** メニューバーの猫アイコンは表示されたまま残る

#### Scenario: 案内画面でも設定を開ける

- **GIVEN** 全体の状態が「gh が見つからない」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 案内と一緒に歯車のボタンが表示される

### Requirement: アプリの終了

ポップオーバーの Quit ボタンを押すと、アプリは終了しなければならない（MUST）。終了後、メニューバーのアイコンは消えなければならない（MUST）。Quit ボタンはキーボードショートカット ⌘Q でも押せなければならない（SHALL）。

#### Scenario: Quit ボタンで終了する

- **GIVEN** ポップオーバーが開いている
- **WHEN** ユーザーが Quit ボタンをクリックする
- **THEN** Mewbell のプロセスが終了する
- **AND** メニューバーから猫アイコンが消える

#### Scenario: ⌘Q で終了する

- **GIVEN** ポップオーバーが開いていてキーボードフォーカスがある
- **WHEN** ユーザーが ⌘Q を押す
- **THEN** Mewbell のプロセスが終了する

### Requirement: 二重起動の防止

Mewbell はユーザーごとに同時に 1 つだけ動かなければならない（MUST）。すでに Mewbell が動いているときに別の Mewbell が起動した場合、後から起動した方はメニューバーにアイコンを出さずに終了しなければならない（MUST）。ほぼ同時に起動した場合でも、残るのは 1 つだけでなければならない（MUST）。ただし、ほかの Mewbell が動いているかどうかを判定できないときは、終了せずに起動を続けてよい（MAY）。テストのホストや SwiftUI プレビューとして起動されたときは、この判定を行わなくてよい（MAY）。

#### Scenario: 起動中にもう一度起動する

- **GIVEN** Mewbell が起動していて、メニューバーに猫アイコンが 1 つ出ている
- **WHEN** ユーザーが別の場所にある Mewbell.app をもう一度起動する
- **THEN** 後から起動した Mewbell はすぐに終了する
- **AND** メニューバーの猫アイコンは 1 つのまま

#### Scenario: ほぼ同時に 2 つ起動する

- **GIVEN** Mewbell が起動していない
- **WHEN** 2 つの Mewbell がほぼ同時に起動する
- **THEN** 片方だけが動き続け、もう片方は終了する

### Requirement: アカウント一覧の表示

全体の状態が「アカウントあり」のとき、ポップオーバーは「無効」以外のアカウントごとの区画を、accounts の並び順で表示しなければならない（SHALL）。「無効」のアカウントの区画は出してはならない（MUST NOT）。すべてのアカウントが「無効」のときは、区画の代わりに、すべてのアカウントが無効であることと、設定ウィンドウを開くボタンを表示しなければならない（SHALL）。区画の見出しにはユーザー名、ホスト名、ホスト種別（GitHub.com / GHE Cloud / Enterprise Server）、トークンの状態（取得中 / 使える / トークンを取れない）を出し、gh のアクティブなアカウントにはそうと分かる印を付けなければならない（SHALL）。「参加しているスレッドだけにする」がオンのアカウントの見出しには、そうと分かる印を付けなければならない（SHALL）。トークンが「使える」アカウントの区画には、見出しに通知の取得の状態を出し、その下に未読の通知をリポジトリ（`owner/name`）ごとにまとめて表示しなければならない（SHALL）。リポジトリは含まれるスレッドの最新の更新日時が新しい順に、スレッドは更新日時が新しい順に並べなければならない（SHALL）。スレッドの行には、種類（Pull request / Issue / Commit / Release / Discussion など）を表すアイコン、件名、理由（`reason`）、更新日時を出さなければならない（SHALL）。種類が Release か Discussion のスレッドには、番号を出してはならない（MUST NOT）。それ以外のスレッドは、種類ではなく `subject.url` で決め、次のすべてを満たすときだけ、行の理由の前にその番号を `#<番号>` の形で出さなければならない（SHALL）。

- `subject.url` が `pulls/<番号>` または `issues/<番号>` の形
- ui「通知のスレッドを開く」でその番号から開く URL を組み立てるときと同じ、次の条件を満たす
  - `subject.url` が API ベース URL と同じオリジンでその下にある
  - `<owner>/<name>` がスレッドのリポジトリと一致する
  - 開く URL を確かめた結果が開く（スキームが `https` で、ホストがアカウントのホストと一致する）

満たさないとき（`subject.url` が無い・`commits/<SHA>` などほかの形・別のホストを指す・リポジトリが一致しないなど）は、番号を出してはならない（MUST NOT）。未読の通知が 0 件のときは、そうと分かる表示を出さなければならない（SHALL）。一覧がポップオーバーに収まらないときは、見出しの「Mewbell」と Quit ボタンを残したまま一覧だけをスクロールできなければならない（SHALL）。トークンの値やその一部、API の URL を表示してはならない（MUST NOT）。

#### Scenario: 2 つのホストのアカウントを表示する

- **GIVEN** `github.com/alice`（使える、アクティブ）と `acme.ghe.com/dave`（使える）がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画の見出しに「github.com — GitHub.com」とアクティブの印が、`dave` の区画の見出しに「acme.ghe.com — GHE Cloud」が表示される
- **AND** どちらも「使える」状態として表示される

#### Scenario: 2 つのアカウントの通知を表示する

- **GIVEN** `github.com/alice`（使える、アクティブ）に `octo/app` の通知が 2 件と `octo/lib` の通知が 1 件あり、`acme.ghe.com/dave`（使える）に `acme/web` の通知が 1 件ある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画（github.com — GitHub.com、アクティブの印付き）の下に `octo/app` と `octo/lib` の見出しと、それぞれのスレッドが表示される
- **AND** `dave` の区画（acme.ghe.com — GHE Cloud）の下に `acme/web` の見出しとスレッドが表示される

#### Scenario: 未読が無い

- **GIVEN** `github.com/alice` の取得ができていて、未読の通知が 0 件
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に、未読の通知が無いことを示す表示が出る

#### Scenario: トークンを取れないアカウント

- **GIVEN** `ghe.example.com/dave` が「トークンを取れない」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` の区画に警告と、実行すべきコマンド `gh auth login --hostname ghe.example.com` が表示される
- **AND** コマンドをクリップボードにコピーするボタンがある

#### Scenario: 無効のアカウントは出さない

- **GIVEN** `github.com/alice`（使える）と `github.com/bob`（無効）がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画だけが表示され、`bob` の区画は無い

#### Scenario: すべてのアカウントが無効

- **GIVEN** `github.com/alice` と `github.com/bob` のどちらも「無効」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** すべてのアカウントが無効であることと、設定ウィンドウを開くボタンが表示される

#### Scenario: 参加しているスレッドだけにしたアカウント

- **GIVEN** `acme.ghe.com/dave` の「参加しているスレッドだけにする」がオン
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` の区画の見出しに、参加しているスレッドだけを表示していることを示す印が出る

#### Scenario: Pull request の番号を出す

- **GIVEN** `github.com/alice` のスレッドのリポジトリが `octo/app`、`subject.url` が `https://api.github.com/repos/octo/app/pulls/42`、理由が `review_requested`
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** そのスレッドの行の件名の下に `#42`、理由、更新日時がこの順に出る

#### Scenario: GHES の Issue の番号を出す

- **GIVEN** `ghe.example.com/dave` のスレッドのリポジトリが `team/svc`、`subject.url` が `https://ghe.example.com/api/v3/repos/team/svc/issues/7`
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** そのスレッドの行に `#7` が出る

#### Scenario: 番号を読めないスレッド

- **GIVEN** `github.com/alice` に、`subject.url` が `https://evil.example.com/repos/octo/app/pulls/42` のスレッドと、種類が Release のスレッドがある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** どちらの行にも番号は出ず、理由と更新日時だけが出る

### Requirement: 案内画面

全体の状態が「アカウントあり」以外のとき、ポップオーバーはアカウント一覧の代わりに、状態ごとに次の案内を表示しなければならない（SHALL）。案内に出すコマンドにはクリップボードへのコピーボタンを付けなければならない（SHALL）。Mewbell がターミナルを開いたり、案内のコマンドを代わりに実行したりしてはならない（MUST NOT）。gh や API のエラー出力をそのまま表示してはならない（MUST NOT）。

- 確認中: 進行中であることを示す表示
- gh が見つからない: gh のインストール方法（`brew install gh`）と、`https://cli.github.com/` をブラウザで開くボタン。設定で gh のパスを上書きしているときは、代わりに、上書きしたパスの gh を使えないことと、設定ウィンドウを開くボタン
- gh が古い: 検出したバージョン、必要なバージョン（2.40.0 以上）、更新方法（`brew upgrade gh`）
- gh を実行できない: gh が期待どおりに応答しなかったことと、手元で確かめるコマンド（`gh --version`）。確かめた後に再読み込みするよう促す
- `hosts.yml` を読めない: 読もうとしたファイルのパスと、`gh auth status` で状態を確かめるよう促す文。設定で gh の設定ディレクトリを上書きしているときは、そのパスが設定で上書きしたものであることと、設定ウィンドウを開くボタンも出す
- 未ログイン: `gh auth login`（GHE の場合は `gh auth login --hostname <host>`）でログインするよう促す文

#### Scenario: gh が無いときの案内

- **GIVEN** 全体の状態が「gh が見つからない」で、gh のパスは上書きしていない
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `brew install gh` とそのコピーボタン、`https://cli.github.com/` を開くボタンが表示される
- **AND** 「Mewbell」の表示と Quit ボタンは残っている

#### Scenario: 開くボタンは固定の URL だけを開く

- **GIVEN** 全体の状態が「gh が見つからない」で、gh のパスは上書きしていない
- **WHEN** ユーザーが `https://cli.github.com/` を開くボタンを押す
- **THEN** 既定のブラウザで `https://cli.github.com/` が開く

#### Scenario: 未ログインの案内

- **GIVEN** 全体の状態が「未ログイン」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `gh auth login` とそのコピーボタンが表示される

#### Scenario: 上書きした gh のパスが使えない

- **GIVEN** ユーザーが設定で gh のパスを `/Users/me/bin/gh` に上書きしていて、そのパスは使えない
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 設定で上書きした gh を使えないことと、設定ウィンドウを開くボタンが表示される
- **AND** `brew install gh` の案内は出ない

#### Scenario: 上書きした設定ディレクトリが読めない

- **GIVEN** ユーザーが設定で gh の設定ディレクトリを存在しない `/Users/me/.gh-old` に上書きした
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `/Users/me/.gh-old/hosts.yml` を読めないことと、それが設定で上書きしたパスであること、設定ウィンドウを開くボタンが表示される

### Requirement: 再読み込みボタン

ポップオーバーには、gh の検出とアカウントの読み取りをやり直す「再読み込み」ボタンがなければならない（SHALL）。「再読み込み」を押すと、通知の取得が「スコープ不足」か「認証エラー」で止まっているアカウントの取得も再開しなければならない（SHALL）。取得を続けているアカウントについては、次の予定の時刻を待たずに `If-Modified-Since` を付けない取得をしなければならない（SHALL。polling「条件付きリクエスト」「ポーリングの間隔」）。

ボタンは、押されたときに押されたことが分かる見た目の反応を返さなければならない（SHALL）。押してから、アカウントの読み直しと、押したことで始まる各アカウントの取得（再開したアカウントの最初の取得を含む）がすべて終わるまで（成功か失敗かは問わない）、ボタンの位置に読み込み中であることが分かる表示を出し、ボタンを押せないようにしなければならない（SHALL）。読み込み中の表示には、支援技術向けに読み込み中であることを伝えるラベルを付けなければならない（SHALL）。レート制限で取得を早めないアカウントの取得は、読み込み中の表示を待たせてはならない（MUST NOT）。

#### Scenario: gh をインストールした後に再読み込みする

- **GIVEN** 全体の状態が「gh が見つからない」で、ユーザーがその後 `brew install gh` と `gh auth login` を済ませた
- **WHEN** ユーザーが「再読み込み」を押す
- **THEN** 確認中の表示を経て、アカウントの区画が表示される

#### Scenario: スコープ不足からの再開

- **GIVEN** `github.com/alice` が「スコープ不足」で、ユーザーがその後スコープを足した
- **WHEN** ユーザーが「再読み込み」を押す
- **THEN** `alice` の区画は最初の取得中の表示を経て、通知の一覧になる

#### Scenario: 一覧のずれを再読み込みで直す

- **GIVEN** `alice` の一覧に、Web で既読にしたスレッドがまだ表示されている
- **WHEN** ユーザーが「再読み込み」を押す
- **THEN** 次の予定の時刻を待たずに `If-Modified-Since` を付けない取得が送られ、既読にしたスレッドは一覧から消える

#### Scenario: 読み込み中の表示

- **GIVEN** `alice` と `bob` が取得を続けている
- **WHEN** ユーザーが「再読み込み」を押す
- **THEN** ボタンの位置に読み込み中の表示が出て、押せなくなる
- **AND** `alice` と `bob` の取得がどちらも終わったところで、元のボタンに戻って押せるようになる

#### Scenario: 取得が失敗しても読み込み中のままにしない

- **GIVEN** `alice` が取得を続けていて、通信ができない
- **WHEN** ユーザーが「再読み込み」を押す
- **THEN** `alice` の取得が通信の失敗で終わったところで、元のボタンに戻る

### Requirement: 通知の取得の状態の表示

ポップオーバーは、アカウントの区画に通知の取得の状態を次のように表示しなければならない（SHALL）。案内に出すコマンドにはクリップボードへのコピーボタンを付けなければならない（SHALL）。API のエラーボディや状態コードの説明文をそのまま表示してはならない（MUST NOT）。

- 最初の取得中: 進行中であることを示す表示
- 取得できた: 最後に成功した時刻
- 失敗して待っている: 取得に失敗していることと次の取得の時刻。最後に取得できた通知の一覧は残す。レート制限のときはそうと分かる表示にする
- スコープ不足: トークンに `repo` も `notifications` も無いこと、`gh auth refresh --hostname <host> --scopes repo` を実行してから再読み込みを押すよう促す文。gh のアクティブでないアカウントには、その前に `gh auth switch --hostname <host> --user <user>` を実行するよう案内する
- 認証エラー: gh のトークンが使えないこと、`gh auth login --hostname <host>` を実行してから再読み込みを押すよう促す文

取得できた・失敗して待っているアカウントの一覧が 10 ページで打ち切ったもの（polling「取得の状態」の打ち切り）のときは、新しい 500 件だけを表示していて、それより古い未読があることを区画に表示しなければならない（SHALL）。打ち切っていないときは、この表示を出してはならない（MUST NOT）。

#### Scenario: アクティブなアカウントのスコープ不足

- **GIVEN** `github.com/alice`（アクティブ）が「スコープ不足」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に `gh auth refresh --hostname github.com --scopes repo` とコピーボタンが表示される

#### Scenario: アクティブでないアカウントのスコープ不足

- **GIVEN** `github.com/bob`（アクティブでない）が「スコープ不足」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `bob` の区画に `gh auth switch --hostname github.com --user bob` と `gh auth refresh --hostname github.com --scopes repo` が、この順にそれぞれのコピーボタン付きで表示される

#### Scenario: 認証エラー

- **GIVEN** `ghe.example.com/dave` が「認証エラー」
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `dave` の区画に `gh auth login --hostname ghe.example.com` とコピーボタンが表示される

#### Scenario: 500 件で打ち切った

- **GIVEN** `github.com/alice` の最後の取得が 10 ページで打ち切られ、一覧に 500 件ある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に、新しい 500 件だけを表示していて、それより古い未読があることが表示される

#### Scenario: 打ち切らなくなると表示が消える

- **GIVEN** `alice` の区画に打ち切りの表示が出ている
- **WHEN** 次の取得が 3 ページで終わる
- **THEN** 打ち切りの表示は消える

### Requirement: 通知のスレッドを開く

ポップオーバーの一覧でスレッドをクリックすると、Mewbell はそのスレッドの Web ページを既定のブラウザで開き、続けてそのスレッドを既読にしなければならない（SHALL。polling「スレッドの既読化」）。開く URL は、API のレスポンスに含まれる URL をそのまま使わず、アカウントの Web ベース URL、リポジトリの `owner/name`、`subject.url` のパスから次のように組み立てなければならない（MUST）。

- `subject.url` が API ベース URL と同じオリジンで、パスが API ベース URL のパスに続く `repos/<owner>/<name>/pulls/<番号>` のとき: `<Web ベース>/<owner>/<name>/pull/<番号>`
- 同じく `.../issues/<番号>` のとき: `<Web ベース>/<owner>/<name>/issues/<番号>`
- 同じく `.../commits/<16 進の SHA>` のとき: `<Web ベース>/<owner>/<name>/commit/<SHA>`
- 種類が Release のとき: `<Web ベース>/<owner>/<name>/releases`
- 種類が Discussion のとき: `<Web ベース>/<owner>/<name>/discussions`
- それ以外（`subject.url` が無い、形が合わない、`subject.url` の `<owner>/<name>` がスレッドのリポジトリと一致しない、などを含む）: `<Web ベース>/<owner>/<name>`

開く前に、組み立てた URL のスキームが `https` で、ホストがアカウントのホストと一致することを確かめ、一致しなければ開いてはならない（MUST NOT）。開かなかったときは、既読にもしてはならない（MUST NOT）。

#### Scenario: Pull request を開く

- **GIVEN** `github.com/alice` のスレッドのリポジトリが `octo/app`、`subject.url` が `https://api.github.com/repos/octo/app/pulls/42`
- **WHEN** ユーザーがそのスレッドをクリックする
- **THEN** 既定のブラウザで `https://github.com/octo/app/pull/42` が開く
- **AND** スレッドは一覧から消え、既読化のリクエストが送られる

#### Scenario: GHES の Issue を開く

- **GIVEN** `ghe.example.com/dave` のスレッドのリポジトリが `team/svc`、`subject.url` が `https://ghe.example.com/api/v3/repos/team/svc/issues/7`
- **WHEN** ユーザーがそのスレッドをクリックする
- **THEN** 既定のブラウザで `https://ghe.example.com/team/svc/issues/7` が開く

#### Scenario: subject.url が別のホストを指している

- **GIVEN** `github.com/alice` のスレッドのリポジトリが `octo/app`、`subject.url` が `https://evil.example.com/repos/octo/app/pulls/42`
- **WHEN** ユーザーがそのスレッドをクリックする
- **THEN** 既定のブラウザで `https://github.com/octo/app` が開く
- **AND** `evil.example.com` の URL は開かない

#### Scenario: subject.url が無い

- **GIVEN** スレッドの種類が CheckSuite で、`subject.url` が無い
- **WHEN** ユーザーがそのスレッドをクリックする
- **THEN** リポジトリのページが開く

### Requirement: 未読バッジ

メニューバーの猫アイコンの横には、全アカウントの未読の一覧（ポップオーバーに表示しているスレッド）の件数の合計を出さなければならない（SHALL）。件数は猫アイコンの右に並べて出さなければならず（SHALL）、件数を出している間も猫アイコンを消してはならない（MUST NOT）。合計が 0 件のときは数字を出してはならず（MUST NOT）、100 件以上のときは `99+` と出さなければならない（SHALL）。件数は一覧が変わったとき（取得、既読化、Done、すべて既読、アカウントの増減、アカウントの無効化と有効化、「参加しているスレッドだけにする」の切り替え）にすぐ変わらなければならない（SHALL）。取得が失敗して待っているアカウントは、最後に取得できたスレッドを数え、止まっているアカウント、トークンを取れないアカウント、無効のアカウントは 0 件として数えなければならない（SHALL）。

合計が 1 件以上のときは、猫アイコンを緑で描かなければならない（SHALL）。件数の文字は緑にせず、メニューバーのほかの文字と同じ色で出さなければならない（SHALL）。合計が 0 件のときは、猫アイコンをメニューバーのほかのアイコンと同じ色で描かなければならない（SHALL）。アイコンと数字は、ライトとダークのどちらの外観でも、緑のときも含めて、メニューバーのほかのアイコンと同じように判別できなければならない（SHALL）。

#### Scenario: 2 つのアカウントの未読

- **GIVEN** `github.com/alice` に未読が 3 件、`acme.ghe.com/dave` に未読が 2 件ある
- **WHEN** 両方の取得が成功する
- **THEN** メニューバーに緑の猫アイコンが出て、その右に `5` と出る

#### Scenario: 未読が無い

- **GIVEN** すべてのアカウントで未読が 0 件
- **WHEN** メニューバーを見る
- **THEN** 猫アイコンだけが、メニューバーのほかのアイコンと同じ色で出て、数字は出ない

#### Scenario: 既読にすると減る

- **GIVEN** メニューバーに `5` と出ている
- **WHEN** ユーザーが一覧のスレッドを 1 つ開く
- **THEN** 次の取得を待たずに `4` になる
- **AND** 猫アイコンは緑のまま出ている

#### Scenario: 最後の 1 件を既読にすると色が戻る

- **GIVEN** メニューバーに緑の猫アイコンと `1` が出ている
- **WHEN** ユーザーがそのスレッドを既読にする
- **THEN** 次の取得を待たずに数字が消え、猫アイコンはメニューバーのほかのアイコンと同じ色に戻る

#### Scenario: 100 件以上

- **GIVEN** 未読の合計が 120 件
- **WHEN** メニューバーを見る
- **THEN** 緑の猫アイコンの右に `99+` と出る

#### Scenario: Done とすべて既読で減る

- **GIVEN** `github.com/alice` に未読が 3 件、`acme.ghe.com/dave` に未読が 2 件あり、メニューバーに `5` と出ている
- **WHEN** ユーザーが `alice` のスレッドを 1 つ Done にし、続けて `dave` の通知をすべて既読にする
- **THEN** 次の取得を待たずに、`4`、`2` の順に変わる

#### Scenario: 外観を切り替えても見える

- **GIVEN** 未読があり、メニューバーに緑の猫アイコンと件数が出ている
- **WHEN** システムの外観をライトとダークで切り替える
- **THEN** どちらの外観でも、緑の猫アイコンと件数の文字が背景から判別できる
- **AND** 件数の文字は、その外観でのメニューバーのほかの文字と同じ色になる

#### Scenario: アカウントを無効にすると減る

- **GIVEN** `github.com/alice` に未読が 3 件、`github.com/bob` に未読が 2 件あり、メニューバーに `5` と出ている
- **WHEN** ユーザーが設定で `bob` を無効にする
- **THEN** すぐに `3` になる

### Requirement: 通知が許可されていないときの案内

macOS の通知が許可されていない（拒否された、またはオフにされた）とき、ポップオーバーは一覧の上に、macOS の通知が切られていることと、システム設定の通知の画面を開くボタンを出さなければならない（SHALL）。許可されたら、ポップオーバーを次に開いたときに案内を消さなければならない（SHALL）。まだ許可を求めていないときと、許可を求めている途中は、案内を出してはならない（MUST NOT）。

#### Scenario: 通知を拒否した

- **GIVEN** ユーザーが Mewbell の通知を許可しなかった
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 通知が切られていることと、システム設定を開くボタンが出る
- **AND** 通知の一覧はいつもどおり表示される

#### Scenario: 後から許可する

- **GIVEN** 案内が出ている
- **WHEN** ユーザーがシステム設定で Mewbell の通知を許可し、ポップオーバーを開き直す
- **THEN** 案内は出ない

### Requirement: スレッドの行の操作

ポップオーバーの一覧のスレッドの行には、ブラウザで開かずにそのスレッドを既読にする「既読にする」と、Done にする「Done にする」の操作がなければならない（SHALL）。2 つの操作は、行にマウスを載せている間だけ行の右端にボタンとして表示し（SHALL）、同じ 2 つを行のコンテキストメニュー（右クリック）にも出さなければならない（SHALL）。ボタンにはツールチップとアクセシビリティのラベルを付けなければならない（SHALL）。ボタンとコンテキストメニューの操作で、ブラウザを開いてはならない（MUST NOT）。ボタンを押したとき、行のクリック（「通知のスレッドを開く」）が同時に起きてはならない（MUST NOT）。「既読にする」は polling「スレッドの既読化」に、「Done にする」は polling「スレッドの Done」に従わなければならない（SHALL）。Done は取り消せないが、1 スレッドだけの操作なので確認を求めない。

#### Scenario: ホバーで操作が出る

- **GIVEN** `github.com/alice` の一覧にスレッド `123` がある
- **WHEN** ユーザーが `123` の行にマウスを載せる
- **THEN** 行の右端に「既読にする」と「Done にする」のボタンが出る
- **AND** マウスを行から外すとボタンは消える

#### Scenario: ボタンで Done にする

- **GIVEN** `123` の行にマウスを載せている
- **WHEN** ユーザーが「Done にする」のボタンを押す
- **THEN** ブラウザは開かず、`123` が一覧からすぐに消え、`DELETE /notifications/threads/123` が送られる

#### Scenario: コンテキストメニューで既読にする

- **GIVEN** `github.com/alice` の一覧にスレッド `123` がある
- **WHEN** ユーザーが `123` の行を右クリックし、「既読にする」を選ぶ
- **THEN** ブラウザは開かず、`123` が一覧からすぐに消え、`PATCH /notifications/threads/123` が送られる

### Requirement: すべて既読のボタン

トークンが「使える」アカウントの区画の見出しには、そのアカウントの通知をすべて既読にするボタンがなければならない（SHALL）。ボタンは、そのアカウントの取得の状態が「取得できた」で、未読の一覧が 1 件以上あるときだけ押せるようにしなければならない（SHALL）。誤操作を防ぐため、1 回目に押したときはリクエストを送らずに、ボタンを確認の表示に変えなければならない（SHALL）。確認の表示は、「参加しているスレッドだけにする」がオフで、一覧が 10 ページで打ち切ったものでない（polling「取得の状態」の打ち切り）アカウントでは、一覧の件数を含むもの（`Mark N as read?` など）にしなければならない（SHALL）。「参加しているスレッドだけにする」がオンのアカウントと、一覧が打ち切ったものであるアカウントでは、件数を出さずに `Mark all as read?` にし、一覧に出ていない未読も既読になることをツールチップとアクセシビリティのラベルで伝えなければならない（SHALL。`PUT /notifications` には絞り込みがなく、また GitHub は通知を `updated_at` の新しい順に返すので、打ち切りで取得しなかった未読はすべて `last_read_at` 以前になるため）。確認の表示のまま 5 秒以内にもう一度押したときだけ、polling「アカウントのすべて既読」に従ってすべて既読にしなければならない（SHALL）。5 秒たったとき、ポップオーバーを閉じたとき、そのアカウントのボタンが押せなくなったとき、一覧の件数か最新のスレッドが変わったときは、リクエストを送らずに元の表示に戻さなければならない（SHALL）。確認の表示は押したアカウントのボタンだけに出し、ほかのアカウントのボタンには影響してはならない（MUST NOT）。

#### Scenario: 2 回押してすべて既読にする

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しの「すべて既読」を押す
- **THEN** ボタンは `Mark 3 as read?` の表示に変わり、リクエストは送られない
- **AND** 5 秒以内にもう一度押すと、`alice` の一覧が空になり、`PUT /notifications` が送られる

#### Scenario: 確認せずに時間が過ぎる

- **GIVEN** ユーザーが `alice` の「すべて既読」を 1 回押し、確認の表示になっている
- **WHEN** 5 秒がたつ
- **THEN** ボタンは元の表示に戻り、リクエストは送られない

#### Scenario: 確認の途中でポップオーバーを閉じる

- **GIVEN** ユーザーが `alice` の「すべて既読」を 1 回押し、確認の表示になっている
- **WHEN** ユーザーがポップオーバーを閉じ、もう一度開いてボタンを 1 回押す
- **THEN** ボタンは確認の表示になるだけで、リクエストは送られない

#### Scenario: 未読が無いとき

- **GIVEN** `github.com/alice` の取得ができていて、未読が 0 件
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の「すべて既読」は押せない

#### Scenario: 取得が失敗して待っているとき

- **GIVEN** `github.com/alice` の取得が失敗して待っていて、最後に取得できた 2 件が表示されている
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の「すべて既読」は押せない

#### Scenario: 確認の途中で新着が届く

- **GIVEN** ユーザーが `alice` の「すべて既読」を 1 回押し、`Mark 3 as read?` の表示になっている
- **WHEN** 5 秒以内の取得で新しいスレッドが届き、一覧が 4 件になる
- **THEN** ボタンは元の表示に戻り、次に押しても確認の表示になるだけでリクエストは送られない

#### Scenario: 参加しているスレッドだけにしたアカウント

- **GIVEN** `acme.ghe.com/dave` の「参加しているスレッドだけにする」がオンで、一覧に 2 件ある
- **WHEN** ユーザーが `dave` の見出しの「すべて既読」を押す
- **THEN** ボタンは `Mark all as read?` の表示に変わり、件数は出ない
- **AND** ツールチップに、一覧に出ていない未読も既読になることが書かれている
- **AND** 5 秒以内にもう一度押すと、`PUT /notifications` が送られる

#### Scenario: 500 件で打ち切ったアカウント

- **GIVEN** `github.com/alice` の「参加しているスレッドだけにする」がオフで、最後の取得が 10 ページで打ち切られ、一覧に 500 件ある
- **WHEN** ユーザーが `alice` の見出しの「すべて既読」を押す
- **THEN** ボタンは `Mark all as read?` の表示に変わり、`Mark 500 as read?` とは出ない
- **AND** ツールチップに、一覧に出ていない未読も既読になることが書かれている
- **AND** 5 秒以内にもう一度押すと、`PUT /notifications` が一覧の最新のスレッドの `updated_at` を `last_read_at` として送られる

### Requirement: 操作の失敗の表示

アカウントに知らせる操作の失敗（polling「操作の失敗の記録」）があるとき、ポップオーバーはそのアカウントの区画に、どの操作（既読・Done・すべて既読）が失敗したかと、未読のままのスレッドは次の取得で一覧に戻ることを、1 つの知らせとして表示しなければならない（SHALL）。この知らせは、幅に合わせて折り返してよい。失敗の理由は、認証エラー、レート制限、それ以外の 3 つに分けて表示しなければならず（SHALL）、HTTP の状態コード、API のエラーボディ、状態コードの説明文を表示してはならない（MUST NOT）。ただし、トークンを持っていなかったためにすべて既読のリクエストを送らなかったとき（一覧から何も外していないとき）は、次の取得で一覧に戻ることを表示してはならない（MUST NOT）。認証エラーのときは、`gh auth login --hostname <host>` を実行するよう促す文をコピーボタン付きで添えなければならない（SHALL）。知らせる失敗が消えたら、表示も消さなければならない（SHALL）。表示は失敗したアカウントの区画だけに出し、ほかのアカウントの区画に出してはならない（MUST NOT）。表示を出している間も、そのアカウントの一覧、スレッドの操作、すべて既読のボタンは今までどおり使えなければならない（SHALL）。

#### Scenario: Done の失敗を表示する

- **GIVEN** `github.com/alice` と `acme.ghe.com/dave` があり、`alice` のスレッドの Done が `500` で失敗した
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に、Done にできなかったことと、次の取得で一覧に戻ることが 1 つの知らせとして表示される（幅に合わせて折り返してよい）
- **AND** `500` という数字やレスポンスの文は表示されない
- **AND** `dave` の区画には表示されない

#### Scenario: 認証エラーで既読にできない

- **GIVEN** `github.com/alice` のスレッドの既読化が `401` で失敗した
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** `alice` の区画に、既読にできなかったことと、`gh auth login --hostname github.com` とコピーボタンが表示される

#### Scenario: トークンが無くてすべて既読を送れなかった

- **GIVEN** `github.com/alice` の一覧に 3 件あり、読み直しの途中でトークンをメモリに持っていない
- **WHEN** ユーザーが `alice` の通知をすべて既読にする
- **THEN** `alice` の区画に、すべて既読にできなかったことが表示される
- **AND** 3 件は一覧に残り、次の取得で一覧に戻るとは表示されない

#### Scenario: 次の取得で表示が消える

- **GIVEN** `alice` の区画に、すべて既読にできなかったことが表示されている
- **WHEN** その後に送った `alice` の取得が成功する
- **THEN** 表示は消え、未読のままのスレッドが一覧に戻っている

### Requirement: 一覧の折りたたみ

ポップオーバーの一覧では、アカウントの区画とリポジトリのグループを、それぞれの見出しから折りたたんだり開いたりできなければならない（SHALL）。折りたたみの操作には、開閉の印（山形）にツールチップを付け、操作にアクセシビリティの説明を付けて、開いているか折りたたんでいるかが読み上げで分かるようにしなければならない（SHALL）。ツールチップと説明にはアカウントのユーザー名とホスト（`alice (github.com)` など）、またはリポジトリの `owner/name` を入れなければならない（SHALL）。折りたたみの操作は、見出しの中身（ユーザー名、ホスト、トークンの状態、印など）の読み上げとツールチップを上書きしてはならない（MUST NOT）。

アカウントの区画を折りたためるのは、次のどちらも満たすときだけにしなければならない（MUST）。

- トークンの状態が「取得中」か「使える」
- 取得の状態が、スレッドの一覧か、未読の通知が無いことを示す表示を出す状態（polling「取得の状態」の「取得できた」か「失敗して待っている」）。最初の取得が失敗して「失敗して待っている」になり、スレッドが 0 件のアカウントも、未読の通知が無いことを示す表示を出すので畳める

それ以外のとき（トークンを取れない、取得の状態がまだ無い（polling「取得の状態」の「最初の取得中」を含む。「参加しているスレッドだけにする」の切り替えや再開の後の最初の取得中も同じ）、スコープ不足や認証エラーで止まったなど）は、畳むものが無いので、そのアカウントの見出しに折りたたみの操作を出してはならない（MUST NOT）。このとき、覚えている折りたたんだ状態は捨てずに残さなければならない（SHALL）。表示は開いた状態と同じにし、何も隠してはならず（トークンを取れないときの案内も、折りたたんだ状態を覚えていても出し続ける）、件数も出してはならない（MUST NOT）。

アカウントの区画を折りたたんだときは、その区画のリポジトリのグループと、未読の通知が無いことを示す表示を隠さなければならない（SHALL）。見出し、「すべて既読」のボタン、通知の取得の状態、500 件で打ち切ったことの表示、操作の失敗の表示は、折りたたんでいても出し続けなければならない（SHALL）。リポジトリのグループを折りたたんだときは、そのグループのスレッドの一覧を隠さなければならない（SHALL）。

折りたたんだアカウントの見出しにはそのアカウントの一覧のスレッドの件数（打ち切ったときは一覧に出している件数。未読バッジと同じ数え方）を、折りたたんだリポジトリの見出しにはそのグループのスレッドの件数を出さなければならない（SHALL）。件数は 1 件以上のときだけ出し、0 件のときは出してはならない（MUST NOT）。件数の表示は、読み上げで「N unread」と読まれるようにしなければならない（SHALL）。折りたたみは表示だけを変え、未読バッジの件数、macOS の通知、ポーリングを変えてはならない（MUST NOT）。

- **GIVEN** `github.com/alice` に `octo/app` の通知が 2 件と `octo/lib` の通知が 1 件ある
- **WHEN** ユーザーが `octo/app` の見出しで折りたたむ

- **THEN** `alice` のリポジトリのグループがすべて隠れ、見出しに `3` と出る

### Requirement: 折りたたみの状態を覚える範囲

折りたたんだ状態は、アカウント（ホストとユーザー名）と、アカウントとリポジトリ（`owner/name`）の組ごとに、Mewbell が起動している間だけ覚えなければならない（SHALL）。ポップオーバーを閉じて開き直しても、折りたたんだ状態は残らなければならない（SHALL）。折りたたんだ状態をディスク（UserDefaults を含む）に保存してはならず（MUST NOT）、起動した直後はすべての区画とグループを開いた状態にしなければならない（SHALL）。

アカウントが一覧から消えたとき（無効にしたときを含む。ただし全体の状態が「確認中」のときは除く。折りたたみは表示だけの状態で、確認が終わると同じアカウントが一覧に戻ることが多いため）は、そのアカウントの折りたたんだ状態（アカウントと、そのアカウントのリポジトリの状態）を捨てなければならない（SHALL）。全体の状態が「アカウントあり」と「確認中」以外になったとき（gh からログアウトした、gh が見つからない、`hosts.yml` を読めないなど）は、すべてのアカウントの折りたたんだ状態を捨てなければならない（MUST）。リポジトリのグループが一覧から消えたこと（スレッドが無くなったこと）だけでは、そのリポジトリの状態を捨ててはならない（MUST NOT）。たとえば、すべて既読にしたリポジトリのグループは一覧から消えるが、その状態は捨てない。そのグループが後で（「参加しているスレッドだけにする」の切り替えや再開の後の最初の成功した取得などで）一覧に戻ったときは、折りたたんだまま戻さなければならない（SHALL）。折りたたんだアカウントの区画のスレッドの一覧が一度消えて（止まった、「参加しているスレッドだけにする」の切り替えや再開の後の最初の取得中など）、アカウントの最初の成功した取得で一覧に戻ったときも、折りたたんだまま戻さなければならない（SHALL）。どちらも、ユーザーが開くか、新着が届くまで折りたたんだままにする。

- **WHEN** 設定で `alice` を無効にし、有効に戻す
- **THEN** `alice` の区画と `octo/app` のグループは開いた状態で表示される

- **WHEN** gh から `alice` をログアウトして全体の状態が「アカウントあり」でなくなり、その後 `gh auth login` でログインし直して `alice` が戻る

#### Scenario: すべて既読にして消えたリポジトリが最初の成功した取得で戻ると畳んだまま

- **WHEN** `alice` の「参加しているスレッドだけにする」を切り替え、その後の `alice` の最初の成功した取得で `octo/app` のスレッドが返る
- **THEN** `octo/app` のグループは折りたたまれたまま表示され、見出しに件数が出る

### Requirement: 新着で折りたたみを開く

折りたたんだアカウントやリポジトリに新着が届いたときは、そのアカウントの区画と、新着を含むリポジトリのグループを開かなければならない（SHALL）。新着は、notifications「新着の通知」で通知の対象になるスレッドと同じものとし、アカウントの「macOS の通知を出す」の設定にかかわらず決めなければならない（MUST）。新着を含まない、ほかの折りたたんだリポジトリのグループを開いてはならない（MUST NOT）。notifications「新着の通知」で通知の対象にならないとき（そのアカウントの最初の成功した取得など）と、既読化・Done・すべて既読が失敗して同じ `updated_at` のまま一覧に戻ったスレッドでは、開いてはならない（MUST NOT）。

- **WHEN** 次の取得で `123` が同じ `updated_at` のまま一覧に戻る
- **THEN** `octo/app` は折りたたまれたまま

### Requirement: Web の通知一覧を開く

一覧に出ているアカウントの区画（無効のアカウントの区画は出さない）の見出しには、そのアカウントのホストの Web の通知一覧を既定のブラウザで開くボタンがなければならない（SHALL）。ボタンは、トークンの状態（取得中・使える・取得できない）と取得の状態（取得中・取得できた・失敗して待っている・スコープ不足・認証エラー）にかかわらず出して、押せるようにしなければならない（SHALL）。開く URL は、アカウントの Web ベース URL（`https://<host>`）に `notifications` を足した `https://<host>/notifications` でなければならず（MUST）、クエリ（`query=` などの絞り込み）を付けてはならない（MUST NOT）。アカウントの「参加しているスレッドだけにする」の設定は URL に反映してはならない（MUST NOT）。開く前に、URL のスキームが `https` で、ホストがアカウントのホストと一致し、ポートとユーザー情報を含まないことを確かめ、満たさなければ開いてはならない（MUST NOT）。ボタンを押しても、スレッドの既読・Done・すべて既読のリクエストを送ってはならず（MUST NOT）、一覧のスレッドを外してはならない（MUST NOT）。ボタンには、開く先のホストを含むツールチップとアクセシビリティのラベル（`Open notifications on <host>` など）を付けなければならない（SHALL）。

#### Scenario: github.com のアカウントの通知一覧を開く

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しの Web の通知一覧のボタンを押す
- **THEN** 既定のブラウザで `https://github.com/notifications` が開く
- **AND** `alice` の一覧の 3 件は残り、既読化のリクエストは送られない

- **WHEN** ユーザーがポップオーバーを開く

### Requirement: ポップオーバーの文字の読みやすさ

ポップオーバーに出す文字（一覧、取得の状態、操作の失敗、案内の文、件数、ボタンの文）は、11pt より小さくしてはならない（MUST NOT）（13pt・11pt は macOS のテキストスタイルの大きさで、`.body` / `.headline` が 13pt、`.subheadline` が 11pt）。スレッドの件名とアカウントの見出しのユーザー名は 13pt で出さなければならない（SHALL）。アカウントの見出しのユーザー名とリポジトリの見出し（`owner/name`）は見出しとして、太字（semibold 以上）にし、薄い色にせず標準の文字色で出さなければならない（SHALL）。

薄い色（システムの副次的な文字色）は、次の補足の情報にだけ使わなければならない（SHALL）: スレッドの行の番号・理由・更新日時、ホスト名とホスト種別、トークンの状態が取得中であることの表示（「Checking gh…」）、gh を探している途中であることの表示（案内画面の「Checking gh…」）、通知の取得中・取得できた時刻の表示（「Loading notifications…」「Updated …」）、未読が無いことの表示、折りたたんだときの件数。この一覧に無い文は、すべて標準の文字色で出さなければならない（SHALL）。例えば、トークンを取れないときやスコープ不足・認証エラーの案内、取得に失敗して待っていることの文（「Rate limited. Retrying at …」など）、操作の失敗、一覧を打ち切ったことの知らせがそうである。すべて既読の確認の文は、確認の途中であることが分かるよう、システムのアクセントカラーで出さなければならない（SHALL）。

文字の色は、システムの文字色（標準・副次的）と、すべて既読の確認の文のシステムのアクセントカラーだけを使い、文字色の指定に独自の色や透明度を掛けた色を使ってはならない（MUST NOT）。マウスを載せたときに件名をボタンの下で消すような、文字色ではなく見た目を重ねる処理は、この決まりに含めない。「コントラストを上げる」をオンにしたときは、薄い色の文字も含めて背景とのコントラストが上がらなければならない（SHALL）。ポップオーバー全体の背景はシステムのマテリアルのままにし、独自の背景で覆ってはならない（MUST NOT）。これにより「透明度を下げる」をオンにしたときは、システムの設定に従って背景が不透明になる。コマンドの行・案内の帯・バッジ・ボタンの囲みには、システムの色を薄く重ねた塗りを敷いてよい。

ポップオーバーのアイコンのうち書体で大きさが決まるもの（種類のアイコン、見出しの山形、トークンの状態、参加のみの印、ベル、ボタンのアイコンなど）は、11pt より小さい書体で描いてはならない（MUST NOT）。取得中の印（`ProgressView`）は、この決まりに含めない。アイコンの色は文字の色の決まりに含めない（種類のアイコン・山形・参加のみの印・ベルは薄い色、トークンの状態と警告は状態を表すシステムの色を使ってよい）。スレッドの行の種類のアイコン、見出しの山形、アカウントの見出しのトークンの状態のアイコンは、同じ幅の列（アイコンの列）の中央に置く。列に置く記号は書体で決まる大きさのまま描き、縮めて列に収めてはならない（MUST NOT）。記号は、倍率 1 と 2 のどちらの画面でも、マウスを載せているときも、欠けずに出なければならない（SHALL）。

文字を大きくしても、ポップオーバーの幅（380pt）は変えてはならず（MUST NOT）、横にスクロールさせてはならない（MUST NOT）。アカウントの見出しは 1 行に収めなければならない（SHALL）。幅が足りないときは、まずホスト名とホスト種別を省略し、それでも足りなければユーザー名の末尾を省略しなければならない（SHALL）。アクティブの印、折りたたんだときの件数、すべて既読の確認の文は省略してはならない（MUST NOT）。リポジトリの見出しは 1 行に収め、収まらないときは中央を省略しなければならない（SHALL）。ユーザー名・ホスト名・リポジトリ名を省略したときは、その文字にマウスを載せたツールチップで全体を読めなければならない（SHALL）。省略していないときは、同じ文のツールチップを出してはならない（MUST NOT）。スレッドの件名は 2 行まで出し、それより長いときは省略しなければならない（SHALL）。

メニューバーのアイコンと件数、設定ウィンドウの文字には、この Requirement は適用しない。

- **AND** 見出しのホスト名は 1 行に省略して出て、件名は 2 行まで出て省略される
- **AND** ホスト名にマウスを載せると、ツールチップで全体が読める

#### Scenario: 長いユーザー名

- **GIVEN** 39 文字のユーザー名のアクティブなアカウントで、すべて既読のボタンを 1 回押して確認の文が出ている
- **WHEN** ユーザーがポップオーバーを見る
- **THEN** 見出しは 1 行のままで、ホスト名が先に省略され、ユーザー名は収まらない分だけ末尾が省略される
- **AND** ユーザー名にマウスを載せると、ツールチップで全体が読める
- **AND** アクティブの印と確認の文は省略されない

#### Scenario: 長いリポジトリ名

- **GIVEN** 長い `owner/name` のリポジトリの未読がある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** リポジトリの見出しは 1 行で、中央が省略される
- **AND** 見出しにマウスを載せると、ツールチップで `owner/name` の全体が読める

#### Scenario: 短い名前

- **GIVEN** `github.com/alice` の `octo/app` に未読がある
- **WHEN** ユーザーが見出しのユーザー名・ホスト名・リポジトリ名にマウスを載せる
- **THEN** 名前は省略されずに出ている
- **AND** 同じ文のツールチップは出ない

#### Scenario: コントラストを上げる

- **GIVEN** システムの「コントラストを上げる」がオン
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 薄い色の文字も含めて、オフのときより背景とのコントラストが高く出る

#### Scenario: 透明度を下げる

- **GIVEN** システムの「透明度を下げる」がオン
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** ポップオーバーの背景は不透明になり、後ろのウィンドウの色が文字の背景に透けない

#### Scenario: すべて既読の確認

- **GIVEN** `github.com/alice` に未読が 3 件ある
- **WHEN** ユーザーがすべて既読のボタンを 1 回押す
- **THEN** 確認の文はシステムのアクセントカラーで、11pt の太字で出る

#### Scenario: Discussion の種類のアイコン

- **GIVEN** `github.com/alice` の `octo/app` に、Discussion のスレッドがある
- **WHEN** ユーザーが倍率 1 の画面でポップオーバーを開き、そのスレッドの行にマウスを載せる
- **THEN** 行の種類のアイコンは、マウスを載せる前も載せている間も、欠けずに出る
- **AND** 種類のアイコンは、ほかのスレッドの行の種類のアイコンや見出しの山形と同じ幅の列の中央に出る

### Requirement: スレッドの行のイベント

スレッドにイベント（polling「スレッドのイベントの取得」）が付いているとき、スレッドの行は、件名の下の行の番号（出すとき）と理由の間に、イベントの表示を出さなければならない（SHALL）。イベントが付いていないときは、今までどおり番号・理由・更新日時だけを出さなければならない（SHALL）。イベントを取っている間やイベントの取得に失敗したときに、そうと分かる表示（読み込み中の印やエラー）を行に出してはならない（MUST NOT）。

イベントの表示は、github-api「スレッドのイベントの決定」のイベント名に、実行者があれば ` by <ログイン名>` を付けたものにしなければならない（SHALL）（例: `Closed by alice`、`Approved by bob`、`Pushed commits`）。表示してよいのは、決まったイベント名と検証済みのログイン名だけで、Timeline の `event` の値やコメントの本文をそのまま出してはならない（MUST NOT）。

#### Scenario: イベントが付いた行

- **GIVEN** `github.com/alice` のスレッドが `octo/app#42`、理由が `subscribed`、イベントが Closed by `alice`、3 分前に更新された
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** そのスレッドの行の件名の下に `#42`、`Closed by alice`、`Watching`、更新日時がこの順に出る

#### Scenario: 実行者の無いイベント

- **GIVEN** スレッドのイベントが Pushed commits で、番号が `#41`、理由が `review_requested`
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行の件名の下に `#41`、`Pushed commits`、`Review requested`、更新日時がこの順に出る

#### Scenario: イベントの無い行

- **GIVEN** 種類が Release のスレッドがある
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行には理由と更新日時だけが出る

### Requirement: スレッドの行の状態のアイコン

スレッドに件名の状態（github-api「スレッドの状態の決定」、polling「スレッドのイベントの取得」）が付いているとき、スレッドの行の種類のアイコンは、種類に加えて状態が分かるものにしなければならない（SHALL）。状態どうしは、記号の形と色の両方で区別しなければならず（MUST）、色だけで区別してはならない（MUST NOT）。VoiceOver では、アイコンを種類と状態（例: 「Pull request, merged」）として読ませなければならない（SHALL）。

状態が「分からない」か付いていないとき、またはスレッドの種類に合わない状態が付いているときは、状態として扱わず、種類だけを表すアイコンを薄い色で出さなければならない（SHALL）。このアイコンは、その種類の状態のアイコン（例: 開いている Pull request の緑のアイコン）と記号の形が同じで色だけが違ってもよい。形と色の両方で区別する決まりは、状態どうしにだけ適用する。状態が分からないことを示すために、種類を表す記号の代わりに種類によらない記号（例: 疑問符）を使ってはならず（MUST NOT）、状態が分からない Pull request と Issue は記号で見分けられなければならない（SHALL）。VoiceOver では、種類だけ（例: 「Pull request」）として読ませなければならない（SHALL）。

#### Scenario: マージした Pull request

- **GIVEN** `github.com/alice` の Pull request のスレッドの状態が Merged
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行のアイコンは、マージした Pull request と分かる記号と色になる

#### Scenario: 開いている Issue と閉じた Issue

- **GIVEN** Issue のスレッドが 2 つあり、状態が Open と Closed as completed
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 2 つの行のアイコンは、記号の形と色の両方が違う

#### Scenario: 状態が分からない

- **GIVEN** Pull request のスレッドのイベントをまだ取っていない
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行のアイコンは、Pull request を表す記号を薄い色で出したものになる
- **AND** VoiceOver では「Pull request」と読まれる

#### Scenario: 状態が分からない Issue

- **GIVEN** Issue のスレッドのイベントを取れなかった
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行のアイコンは、Issue を表す記号を薄い色で出したものになる
- **AND** VoiceOver では「Issue」と読まれる

#### Scenario: 種類に合わない状態

- **GIVEN** Issue のスレッドに、Pull request にしか無い状態（Merged）が付いている
- **WHEN** ユーザーがポップオーバーを開く
- **THEN** 行のアイコンは、状態が分からない Issue と同じになる

### Requirement: アカウントの見出しのトークンの状態の読み上げ

ポップオーバーのアカウントの見出しに出すトークンの状態の表示（アイコンと取得中の印）には、状態ごとの名前を付け、VoiceOver ではその名前を読ませなければならない（SHALL）。記号の既定の名前（警告の三角など）を読ませてはならない（MUST NOT）。ツールチップにも同じ名前を出さなければならない（SHALL）。名前は次のとおりにしなければならない（SHALL）。

- トークンを取得中: `Getting token`
- トークンが「使える」で、取得が止まっていない: `Ready`
- トークンが「使える」が、取得がスコープ不足か認証エラーで止まっている（polling「取得の状態」）: `Stopped`
- トークンを取れない: `No token`

「止まっている」と「トークンを取れない」は同じ記号と色で出してよいが、名前は別にしなければならない（MUST）。トークンの状態の表示を変えても、見出しの記号・色・配置、折りたたみの操作の読み上げ（ui「一覧の折りたたみ」）は変えてはならない（MUST NOT）。名前にトークンの値やその一部、API の URL を含めてはならない（MUST NOT）。

#### Scenario: 使えるトークンを読み上げる

- **GIVEN** `github.com/alice` のトークンが「使える」で、通知を取得できている
- **WHEN** VoiceOver でポップオーバーの `alice` の見出しを読む
- **THEN** トークンの状態が `Ready` と読まれる
- **AND** アイコンにマウスを載せると、ツールチップに `Ready` と出る

#### Scenario: 止まっているアカウントとトークンを取れないアカウントを読み分ける

- **GIVEN** `github.com/bob` のトークンは「使える」が取得がスコープ不足で止まっていて、`ghe.example.com/dave` は「トークンを取れない」
- **WHEN** VoiceOver でポップオーバーの両方の見出しを読む
- **THEN** `bob` のトークンの状態は `Stopped`、`dave` のトークンの状態は `No token` と読まれる
- **AND** どちらのアイコンも同じ黄色の警告の記号のまま

#### Scenario: 取得中のトークンを読み上げる

- **GIVEN** `github.com/carol` のトークンを gh から取得中
- **WHEN** VoiceOver でポップオーバーの `carol` の見出しを読む
- **THEN** トークンの状態が `Getting token` と読まれる
- **AND** 取得中の印にマウスを載せると、ツールチップに `Getting token` と出る

### Requirement: ポップオーバーの押せる要素のホバーの反応

ポップオーバーの次の要素は、マウスを載せている間、押せる範囲に薄い塗りを出して、押せることと押したときに反応する範囲が分かるようにしなければならない（SHALL）。押している間は、マウスを載せているときより濃い塗りにしなければならない（SHALL）。

- アイコンだけのボタン: 見出しの歯車と再読み込み、スレッドの行の「既読にする」と「Done にする」、アカウントの見出しの Web の通知一覧のボタンとすべて既読のボタン（確認の表示のときも含む）、コマンドの行のコピーのボタン
- スレッドの行（クリックでスレッドを開く範囲）
- アカウントの見出しとリポジトリの見出しの、折りたたみの操作の範囲

塗りは、システムの文字色を薄く重ねた角丸の塗りにし、独自の色を使ってはならない（MUST NOT）。これは「ポップオーバーの文字の読みやすさ」が許すボタンの囲みの塗りであり、文字の色を変えてはならない（MUST NOT。すべて既読の確認の文はアクセントカラーのまま）。マウスを外したら塗りを消さなければならない（SHALL）。押せないとき（再読み込み中の再読み込みのボタン、押せないすべて既読のボタン）と、折りたたみの操作を出さない見出しには、塗りを出してはならない（MUST NOT）。塗りを出しても、行と見出しの高さ、アイコンと文字の位置、件名の折り返しは変えてはならない（MUST NOT）。

スレッドの行では、行の塗りはマウスを載せた行の全体に出し、「既読にする」と「Done にする」のボタンを出している間も、ボタンの下を含めて行の全体に出し続けなければならない（SHALL）。ボタンにマウスを載せたときは、行の塗りの上にボタンの塗りを重ねて出さなければならない（SHALL）。リポジトリの見出しの折りたたみの操作の範囲は、見出しの行の幅いっぱいにしなければならない（SHALL）。アカウントの見出しの折りたたみの操作の範囲は、見出しの行のうち、Web の通知一覧とすべて既読のボタンの手前までの幅いっぱいにし（SHALL）、それらのボタンと重ねてはならない（MUST NOT）。

システム標準の押しボタン（Quit、Open Settings…、Open cli.github.com など）は、macOS の標準の見た目のままにし、独自の塗りを付けてはならない（MUST NOT）。

#### Scenario: スレッドの行にマウスを載せる

- **GIVEN** `github.com/alice` の一覧にスレッド `123` がある
- **WHEN** ユーザーが `123` の行にマウスを載せる
- **THEN** `123` の行の全体に薄い塗りが出て、右端に「既読にする」と「Done にする」のボタンが出る
- **AND** 件名の折り返しと行の高さは、マウスを載せる前と変わらない
- **AND** マウスを行から外すと、塗りとボタンは消える

#### Scenario: 行の操作のボタンにマウスを載せる

- **GIVEN** `123` の行にマウスを載せている
- **WHEN** ユーザーがマウスを「Done にする」のボタンの上へ動かす
- **THEN** 行の塗りは出たままで、「Done にする」のアイコンの後ろに角丸の塗りが重なって出る
- **AND** 「既読にする」のアイコンの後ろには塗りが出ない

#### Scenario: 見出しのアイコンのボタンにマウスを載せる

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しのすべて既読のボタンにマウスを載せ、続けて Web の通知一覧のボタンにマウスを載せる
- **THEN** マウスを載せているボタンのアイコンの後ろにだけ、角丸の薄い塗りが出る

#### Scenario: すべて既読の確認の表示

- **GIVEN** ユーザーが `alice` の「すべて既読」を 1 回押し、`Mark 3 as read?` の表示になっている
- **WHEN** ユーザーがそのボタンにマウスを載せる
- **THEN** 確認の文の後ろに角丸の薄い塗りが出て、文はアクセントカラーのまま

#### Scenario: 押せないボタン

- **GIVEN** `github.com/alice` の取得ができていて、未読が 0 件
- **WHEN** ユーザーが `alice` の見出しのすべて既読のボタンにマウスを載せる
- **THEN** 塗りは出ない

#### Scenario: リポジトリの見出しにマウスを載せる

- **GIVEN** `github.com/alice` に `octo/app` の通知が 2 件ある
- **WHEN** ユーザーが `octo/app` の見出しの、リポジトリ名より右の空いたところにマウスを載せる
- **THEN** 見出しの行の幅いっぱいに薄い塗りが出る
- **AND** そこを押すと `octo/app` が折りたたまれる

#### Scenario: アカウントの見出しにマウスを載せる

- **GIVEN** `github.com/alice` の一覧に 3 件ある
- **WHEN** ユーザーが `alice` の見出しの、ホスト名と Web の通知一覧のボタンの間の空いたところにマウスを載せる
- **THEN** 山形から Web の通知一覧のボタンの手前までに薄い塗りが出て、すべて既読と Web の通知一覧のボタンには塗りが出ない
- **AND** そこを押すと `alice` の区画が折りたたまれ、すべて既読のボタンは確認の表示にならない

#### Scenario: 折りたたみの操作を出さない見出し

- **GIVEN** `ghe.example.com/dave` が「トークンを取れない」
- **WHEN** ユーザーが `dave` の見出しにマウスを載せる
- **THEN** 見出しに塗りは出ない

#### Scenario: 標準の押しボタン

- **GIVEN** ポップオーバーが開いている
- **WHEN** ユーザーが Quit ボタンにマウスを載せる
- **THEN** Quit ボタンは macOS の標準の押しボタンの見た目のままで、独自の塗りは出ない
